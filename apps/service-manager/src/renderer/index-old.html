Nestia SDK 빌드

📘 Nestia SDK란?
NestJS API를 기반으로 타입 안전한 클라이언트 SDK를 자동 생성합니다.
  • ✅ 자동 타입 생성: 서버 DTO → 클라이언트 타입
  • ✅ 타입 안전성: 컴파일 타임에 API 오류 감지
  • ✅ 런타임 검증: typia로 데이터 유효성 검사
  • ✅ Swagger 생성: API 문서 자동 생성

💡 언제 실행하나요?
  • 서버 API 컨트롤러를 추가/수정한 후
  • DTO (Request/Response) 구조를 변경한 후
  • 클라이언트에서 타입 에러가 발생할 때
💡 출력 위치:
• SDK: apps/api/src/api/
• Swagger: apps/api/swagger.json

Docker 관리

⚠️ Docker 완전 초기화
이 작업은 다음을 모두 삭제합니다:
  • 🗑️ 컨테이너: 모든 Papyrus Docker 컨테이너 (MySQL, Nginx)
  • 🗑️ 볼륨: 모든 데이터베이스 데이터 (영구 삭제)
  • 🗑️ 이미지: MySQL 및 Nginx 이미지
  • 🗑️ 네트워크: 사용되지 않는 네트워크

💡 언제 사용하나요?
  • Docker 환경을 처음부터 다시 구성하고 싶을 때
  • 데이터베이스를 완전히 초기화하고 싶을 때
  • Docker 관련 문제가 발생했을 때

⚠️ 주의: 이 작업은 되돌릴 수 없습니다. 모든 데이터가 영구 삭제됩니다.

🔨 STEP 1. 스키마 빌드 필수 단계
📖 스키마 빌드란?
libs/db/prisma/ 폴더에 분산된 여러 .prisma 파일들을 하나의 apps/api/prisma/schema.prisma 파일로 자동 병합하는 과정입니다.
  • base.prisma: 데이터베이스 연결 설정
  • common.prisma: 공통 모델 (Tag, Attachment 등)
  • country.prisma, event.prisma 등: 도메인별 모델
🔨 스키마 빌드 실행 (Schema Build)
🎯 목적: 모듈화된 스키마 파일들을 하나의 통합 스키마로 병합합니다.
  • 입력: libs/db/prisma/*.prisma (base, common, country, event, user 등)
  • 출력: apps/api/prisma/schema.prisma (통합 파일)
  • 작동 방식: 모든 분산 파일을 읽어 하나의 파일로 자동 병합
✅ 언제 실행?
  • libs/db/prisma/ 폴더의 어떤 .prisma 파일이든 수정한 직후
  • 새로운 모델, 필드, 관계를 추가/수정/삭제한 경우
  • 데이터베이스 타입, 인덱스, 제약조건을 변경한 경우
⚠️ 주의: 빌드 없이 마이그레이션하면 이전 스키마가 적용되어 예상과 다른 결과가 나올 수 있습니다!
✅ 스키마 검증 (Schema Validation)
🎯 목적: 통합된 스키마의 문법, 구조, 관계가 올바른지 검증합니다.
  • 문법 검증: Prisma 문법 오류 체크 (오타, 잘못된 키워드 등)
  • 타입 검증: 필드 타입이 올바른지 확인 (String, Int, DateTime 등)
  • 관계 검증: @relation의 참조가 올바른지 확인
  • 제약조건 검증: @unique, @id, @@index 등의 유효성 확인
✅ 언제 실행?
  • 스키마 빌드 실행 직후 (마이그레이션 전)
  • 복잡한 관계나 제약조건을 추가한 경우
  • 마이그레이션 오류가 발생했을 때 원인 파악용
💡 팁: 검증 성공 시에만 마이그레이션을 진행하면 실수를 줄일 수 있습니다.
🔄 Prisma Client 생성 (Generate Client)
🎯 목적: 스키마를 기반으로 타입 안전한 TypeScript 데이터베이스 클라이언트를 자동 생성합니다.
  • 생성 위치: node_modules/.prisma/client/
  • 생성 내용: 모든 모델에 대한 TypeScript 타입 + CRUD 메서드
  • 타입 안전성: 컴파일 시점에 데이터베이스 오류를 잡을 수 있음
  • 자동완성: IDE에서 필드명, 메서드 자동완성 지원
✅ 언제 실행?
  • 자동 실행: 마이그레이션 성공 후 자동으로 실행됨
  • 수동 실행: 스키마는 변경하지 않고 Client만 재생성하고 싶을 때
  • 오류 해결: Client 관련 TypeScript 에러가 발생할 때
  • 의존성 업데이트: Prisma 패키지를 업데이트한 후
💡 예시: User 모델 추가 → Client 생성 → 코드에서 prisma.user.create() 사용 가능
💡 권장 워크플로우:
1️⃣ libs/db/prisma/*.prisma 파일 수정 → 2️⃣ 🔨 스키마 빌드 실행 → 3️⃣ ✅ 스키마 검증 (오류 확인) → 4️⃣ 마이그레이션 탭으로 이동하여 변경사항 적용 → 5️⃣ 🔄 Client 생성 (마이그레이션 후 자동 실행됨)
🚀 STEP 2. 마이그레이션 실행 DB 변경 적용
⚠️ 마이그레이션이란?
데이터베이스 스키마 변경사항을 안전하게 적용하고 버전 관리하는 방식입니다.
  • 자동 생성: 스키마 차이를 비교하여 SQL 파일 자동 생성
  • 버전 관리: 모든 변경 히스토리를 migrations/ 폴더에 저장
  • 롤백 가능: 문제 발생 시 이전 버전으로 되돌릴 수 있음
  • 팀 협업: Git으로 마이그레이션 파일을 공유하여 동일한 스키마 유지
📝 네이밍 규칙 (Migration Naming Convention)
📝 마이그레이션 명칭 규칙
기본 원칙:
  • 영문 소문자와 언더스코어(_)만 사용
  • 동사로 시작하여 무엇을 하는지 명확히 표현
  • 구체적이고 설명적인 이름 사용
  • 공백, 대문자, 특수문자 사용 금지
📋 작업별 명칭 패턴:
  • 테이블 생성: create_[테이블명]_table
    예: create_user_profile_table, create_event_category_table
  • 필드 추가: add_[테이블명]_[필드명]_field
    예: add_user_email_field, add_event_start_date_field
  • 필드 수정: modify_[테이블명]_[필드명]_to_[타입]
    예: modify_user_age_to_int, modify_event_title_to_text
  • 필드 제거: remove_[테이블명]_[필드명]_field
    예: remove_user_nickname_field
  • 인덱스 추가: add_index_on_[테이블명]_[필드명]
    예: add_index_on_user_email, add_index_on_event_date
  • 관계 추가: add_relation_[테이블1]_to_[테이블2]
    예: add_relation_user_to_post, add_relation_event_to_category
  • 테이블 이름 변경: rename_[기존명]_to_[새이름]_table
    예: rename_old_user_to_member_table
  • 초기 설정: init 또는 initial_setup
    예: init, initial_database_setup
✅ 좋은 예시:
  • add_user_birth_date_field - 명확하고 구체적
  • create_event_participant_table - 테이블 생성 의도 명확
  • add_index_on_country_code - 인덱스 추가 위치 명확
  • modify_event_status_to_enum - 변경 내용 명확
❌ 나쁜 예시:
  • update - 너무 모호함
  • fix_bug - 무엇을 고쳤는지 불명확
  • addUserField - camelCase 사용 (언더스코어 사용할 것)
  • new-table - 하이픈 사용 금지 (언더스코어 사용)
  • 임시작업 - 한글 사용 금지 (영문 사용)
💡 팁:
  • Git 커밋 메시지처럼 미래의 자신과 팀원이 이해할 수 있게 작성
  • 약어보다는 전체 단어 사용 (예: usr ❌ → user ✅)
  • 날짜는 Prisma가 자동으로 타임스탬프 추가하므로 이름에 포함 불필요
⚠️ 주의사항
  • 마이그레이션은 실제 데이터베이스를 변경합니다
  • 실행 전에 반드시 백업을 권장합니다
  • 프로덕션 환경에서는 팀원과 협의 후 실행하세요
🎨 STEP 3. 데이터 확인 선택 사항
🎨 Prisma Studio란?
데이터베이스를 시각적으로 탐색하고 편집할 수 있는 웹 기반 GUI 도구입니다.
  • 테이블 브라우징: 모든 테이블과 레코드를 한눈에 확인
  • 데이터 편집: 레코드 추가, 수정, 삭제 가능
  • 관계 탐색: 테이블 간의 관계를 시각적으로 확인
  • 필터링: 조건에 맞는 데이터만 검색
🌐 Studio 실행 후 자동으로 http://localhost:5555에서 접속할 수 있습니다.

🌱 Seed 데이터 삽입 초기 데이터
🌱 Seed란?
데이터베이스에 초기 데이터를 삽입하는 작업입니다.
  • 테스트 데이터: 개발 환경에서 테스트용 데이터 생성
  • 기본 데이터: 애플리케이션 실행에 필요한 기본 데이터 (관리자 계정, 카테고리 등)
  • 반복 실행: 여러 번 실행해도 안전하도록 중복 체크 포함
📝 실행 순서
  1. TypeScript: apps/api/prisma/seed.ts 파일의 로직 실행

💡 환경 선택:
  • development: 개발 환경용 전체 샘플 데이터 (대륙, 국가, 역사적 국가, 카테고리, 관리자 계정)
  • test: 테스트 환경용 (현재 비어있음, 필요시 구현)
💡 권장: 개발 환경에서는 Development를 선택하세요
