🔨 STEP 1. 스키마 빌드 필수 단계
📖 스키마 빌드란?
libs/db/prisma/ 폴더에 분산된 여러 .prisma 파일들을 하나의 apps/api/prisma/schema.prisma 파일로 자동 병합하는 과정입니다.
  • base.prisma: 데이터베이스 연결 설정
  • common.prisma: 공통 모델 (Tag, Attachment 등)
  • country.prisma, event.prisma 등: 도메인별 모델
💡 언제 실행하나요? libs/db/prisma/ 폴더의 .prisma 파일을 수정한 직후에 실행하세요.
🚀 STEP 2. 마이그레이션 실행 DB 변경 적용
⚠️ 마이그레이션이란?
데이터베이스 스키마 변경사항을 안전하게 적용하고 버전 관리하는 방식입니다.
  • 자동 생성: 스키마 차이를 비교하여 SQL 파일 자동 생성
  • 버전 관리: 모든 변경 히스토리를 migrations/ 폴더에 저장
  • 롤백 가능: 문제 발생 시 이전 버전으로 되돌릴 수 있음
  • 팀 협업: Git으로 마이그레이션 파일을 공유하여 동일한 스키마 유지
📝 네이밍 규칙: 소문자와 언더스코어(_)만 사용하여 명확하게 작성하세요.
예시: add_필드명, create_테이블명, update_인덱스명
⚠️ 주의사항
  • 마이그레이션은 실제 데이터베이스를 변경합니다
  • 실행 전에 반드시 백업을 권장합니다
  • 프로덕션 환경에서는 팀원과 협의 후 실행하세요
🎨 STEP 3. 데이터 확인 선택 사항
🎨 Prisma Studio란?
데이터베이스를 시각적으로 탐색하고 편집할 수 있는 웹 기반 GUI 도구입니다.
  • 테이블 브라우징: 모든 테이블과 레코드를 한눈에 확인
  • 데이터 편집: 레코드 추가, 수정, 삭제 가능
  • 관계 탐색: 테이블 간의 관계를 시각적으로 확인
  • 필터링: 조건에 맞는 데이터만 검색
🌐 Studio 실행 후 자동으로 http://localhost:5555에서 접속할 수 있습니다.
