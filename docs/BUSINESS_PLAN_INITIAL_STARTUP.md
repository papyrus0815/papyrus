## 1. 사업 개요

### 1.1 사업명
**Papyrus** (파피루스) - 과거부터 현재까지 모든 지식을 연결하는 통합 정보 플랫폼

### 1.2 사업 요약 (200자)
역사적 사건부터 현대 시사까지 구조화된 형태로 관리하고, 사건·인물·국가·조직 간 복잡한 관계를 자동으로 연결하여 시각화하는 통합 데이터 플랫폼. 교육기관, 언론사, 연구소, 콘텐츠 크리에이터 등 B2B/B2C 시장을 타겟으로 하며, 향후 사용자 참여 기능을 통해 지식 공유 생태계를 구축합니다.

### 1.3 사업 유형
- **업종**: 소프트웨어 개발 및 공급업
- **사업 분야**: IT/소프트웨어, 빅데이터, 에듀테크, 디지털 콘텐츠
- **사업 모델**: B2B SaaS + B2G 프로젝트

## 2. 창업 동기 및 목표

### 2.1 창업 동기

#### 문제 인식
현대 사회에서 역사와 시사 정보는 다음과 같은 문제를 안고 있습니다:

1. **정보의 분산**: 위키피디아, 뉴스 DB, 학술 자료 등이 각각 분리되어 통합적 이해 곤란
2. **비구조화**: 자유 형식의 텍스트로만 존재하여 데이터 분석 불가
3. **관계 파악 어려움**: 사건-인물-국가-조직 간 복잡한 관계를 직관적으로 이해하기 어려움
4. **데이터 접근성**: 전문 데이터베이스는 비용이 높고 사용이 복잡
5. **역사적 맥락 부재**: 현대 사건을 이해할 때 역사적 배경 확인이 어려움

#### 기회 포착
- 교육 기관: 체계적인 역사 교육 자료 필요
- 언론사/싱크탱크: 복잡한 국제 관계 분석 도구 부족
- 연구 기관: 구조화된 데이터베이스 수요
- **콘텐츠 크리에이터**: 정확한 자료와 시각 자료 필요 (역사/시사/밀덕 유튜버)
- 일반 대중: 복잡한 정보를 쉽게 이해할 수 있는 도구 부재

**→ 구조화된 데이터와 시각화로 정보 이해를 돕는 플랫폼의 필요성 인식**

## 3. 사업 아이템 설명

### 3.1 제품/서비스 개요

**Papyrus**는 역사부터 현대까지 모든 사건·인물·국가·조직 정보를 **구조화된 형태로 관리**하고, 자동으로 **관계를 연결·시각화**하는 통합 데이터 플랫폼입니다.

#### 핵심 특징
1. **구조화된 데이터**: 자유 형식이 아닌 체계적인 입력 폼으로 데이터 품질 확보
2. **자동 관계 연결**: 멘션 시스템으로 사건↔인물↔조직 자동 연결
3. **시각화**: 교전국 그래프, 타임라인, 관계도
4. **시간 통합**: 역사적 사건과 현대 시사를 하나의 시스템에서 관리
5. **확장성**: 향후 사용자 참여 기능을 통한 지식 생태계 구축 예정

### 3.2 주요 기능

#### 3.2.1 사건 관리 (Event)
```
입력 항목:
  - 기본 정보: 제목, 설명, 날짜, 카테고리, 썸네일
  - 상세 정보: 군사(교전국 그래프), 외교(참가국), 경제(정책) 등
  - 위치 정보: 대륙, 국가, 도시
  - 관계 설정: 관련 인물/조직/군부대/상하위 사건

특화 기능:
  ✓ 교전국 관계 그래프 (네트워크 다이어그램)
  ✓ 멘션 시스템 (@인물, #조직 자동 연결)
  ✓ 타임라인 시각화
  ✓ 계층 구조 (상위/하위 사건)
```

**실제 사례**: 
- 역사: "제2차 세계대전" 입력 시 → 교전국 그래프로 연합국/추축국 시각화 → 주요 전투 하위 사건으로 연결
- 현대: "트럼프 관세 정책" 입력 시 → 관련 인물(트럼프, 재무장관) 자동 연결 → 2018년 무역전쟁 상위 사건으로 연결

#### 3.2.2 인물/조직/국가 관리
```
인물: 생몰년, 직업, 직위, 소속, 참여 사건
국가: 정치/경제 통계, 행정부 인사, 역사적 국가 연결
조직: 정부/정당/군사/종교/기업
```

#### 3.2.3 사용자 기능 (향후 로드맵)
```
2차년 이후 개발 예정:
  ✓ 회원가입/로그인
  ✓ 사용자 정보 입력 기능
  ✓ 협업 편집 (위키 방식)
  ✓ 댓글/토론
  ✓ 기여도 시스템 (포인트/배지)
  ✓ 커뮤니티 검증 (투표/리뷰)

→ 1차년은 관리자 중심 플랫폼으로 시작
→ 2차년부터 사용자 참여 기능 단계적 추가
```

### 3.3 기술적 우위

#### 완성도 (프로토타입 수준, 정직하게 표현)
```
✅ 구축 완료:
  - Backend API 핵심 기능 (NestJS, Prisma, MySQL)
  - Database 설계 및 구축 (22개 모듈화 스키마)
  - Admin Web 프로토타입 (React 19, TypeScript)
  - Service Manager (Electron 앱, 개발 도구)
  - DevOps 기본 설정 (Docker, K8s)

🔄 개발 진행 중:
  - User Web (초기 단계)
  - UI/UX 디자인 방향성
  - 사용자 인터페이스

⏳ 앞으로 필요한 작업:
  - User Web 완성 (6개월 예상)
  - 디자인 시스템 구축
  - 인터페이스 확정
  - 사용성 테스트 및 개선
  - 성능 최적화
  - 테스트 커버리지 확보
```

**→ 프로토타입 보유 = 대부분의 창업팀보다 앞서 있음 (아이디어만 있는 팀이 대다수)**

**현실적 평가**:
- 기술적 기반: 완성 ✅
- 제품 완성도: 약 40% (정직한 평가)
- 완성까지 기간: 6~9개월 필요
- 경쟁력: 프로토타입만으로도 상위 20% 수준

#### 기술 스택
```
Backend: NestJS 11, Prisma 7, MySQL 8
Frontend: React 19, TypeScript 5.9, Vite 7
Architecture: Clean Architecture, CQRS, Feature-Sliced Design
DevOps: Nx 모노레포, Docker, Kubernetes
```

#### 독창적 기술
1. **교전국 그래프 에디터**: 복잡한 전쟁/분쟁 관계를 인터랙티브하게 시각화
2. **멘션 시스템**: 설명 작성 중 @, # 입력 시 자동 연결
3. **다단계 폼**: 카테고리별 맞춤 입력 폼 (군사/외교/정치 등)
4. **역사-현대 연결**: 과거 국가와 현대 국가 자동 매핑

### 4.3 시장 트렌드

1. **디지털 전환 가속**: 문화유산 디지털화 예산 증가
2. **에듀테크 성장**: 온라인 교육 시장 연평균 15% 성장
3. **지정학적 리스크 관리**: 미중 갈등, 러우 전쟁 등으로 국제 정세 분석 수요 급증
4. **팩트체크 중요성**: 가짜뉴스 증가로 정확한 정보 구조화 필요
5. **데이터 기반 의사결정**: 구조화된 데이터 수요 증가
6. **크리에이터 경제 성장** 🆕: 
   - 역사/시사/밀리터리 콘텐츠 유튜버 급증
   - 정확한 자료와 고품질 시각 자료 수요 증가
   - 구독자들의 팩트체크 요구 증가

## 5. 경쟁 분석

### 5.1 직접 경쟁자

#### 위키피디아
```
강점: 
  - 방대한 데이터
  - 높은 인지도
  - 무료

약점:
  - 자유 형식 (구조화 부족)
  - 관계 시각화 없음
  - 복잡한 편집 문법
  - 데이터 분석 불가

Papyrus의 차별점:
  ✅ 완전히 구조화된 데이터
  ✅ 자동 관계 연결 및 시각화
  ✅ 직관적인 관리 UI
  ✅ API 제공으로 재활용 가능
  ✅ 향후 사용자 참여 기능 제공
```

#### 뉴스 데이터베이스 (KIND, BigKinds 등)
```
강점:
  - 뉴스 아카이브
  - 키워드 검색

약점:
  - 현재 사건만 다룸
  - 단순 키워드 검색
  - 관계 정보 없음

Papyrus의 차별점:
  ✅ 역사+현재 통합
  ✅ 구조화된 데이터
  ✅ 관계 시각화
  ✅ 향후 사용자 참여 기능
```

### 5.2 간접 경쟁자

- **학술 DB** (RISS, DBpia): 논문만 다룸, 일반 사건 없음
- **타임라인 앱** (TimelineJS): 시각화만, 데이터 관리 기능 부족
- **관계도 도구** (Miro, Notion): 범용 도구, 역사/시사 특화 아님

### 5.3 경쟁 우위 정리

| 항목 | Papyrus | 위키피디아 | 뉴스DB | 학술DB |
|------|---------|-----------|--------|--------|
| 구조화 데이터 | ✅ | ❌ | △ | ✅ |
| 관계 시각화 | ✅ | ❌ | ❌ | ❌ |
| 역사+현대 | ✅ | △ | ❌ | ❌ |
| API | ✅ | △ | ❌ | △ |
| 사용자 참여 | △ (향후) | ✅ | ❌ | ❌ |

**→ 유일하게 구조화+시각화+역사-현대 통합을 모두 제공**

  - 변화 대응 빠름

  - 제품 완성
  - 초기 고객 확보
  - 피드백 반영

✅ 위험 최소화
  - 시장 검증 전 대규모 채용 회피

  - 실패 시 손실 최소화

✅ 입증된 역량
