## 1. 프로젝트 개요

### 1.1 프로젝트명
**Papyrus** (파피루스)

### 1.2 한 줄 설명
**정보 파편화를 해결하고**, 과거부터 현재까지 모든 사건, 인물, 국가, 조직 간의 복잡한 관계를 **하나로 통합**하여 관리하고 시각화하는 **종합 시사·역사 데이터 관리 플랫폼**

> 💼 **쉬운 비유**: 
> "회사에 인사관리 ERP가 있듯이, 역사·시사 정보를 위한 전문 ERP입니다"
> 
> - 엑셀로 인사관리 하지 않고 ERP를 쓰듯이
> - 노션으로 역사 관리 하지 않고 Papyrus를 씁니다

> 💡 **핵심 차별점**: 
> - **정보 파편화 완전 해결** - 나무위키처럼 수십 개 문서를 탐색할 필요 없이 한 곳에서 모든 관련 정보 조회
> - **역사+현대 통합** - 역사 자료뿐만 아니라 현대 사건과 실시간 정보까지 통합 관리
> - **자동 관계 연결** - 사건-인물-국가 간 관계를 자동으로 맵핑하여 즉시 탐색 가능
> - **도메인 특화 시스템** - 범용 도구(노션)가 아닌 역사·시사 전문 설계
> - **🎯 데이터를 쌓아가는 즐거움** - 내 손으로 지식을 구조화하고, 관계를 연결하며, 시각화되는 것을 보는 재미와 보람

### 1.3 프로젝트 배경

현대 사회에서 역사·정치·사회 정보는 다음과 같은 심각한 문제점을 가지고 있습니다:

#### 핵심 문제: 정보 파편화 (Information Fragmentation)

##### 🔴 기존 서비스의 한계

**나무위키/위키피디아**
```
❌ 정보가 개별 문서로 분산
   → "트럼프 관세 정책" 문서
   → "미중 무역전쟁" 문서 (별도)
   → "중국 WTO 가입" 문서 (별도)
   → 이들의 관계를 파악하려면 수십 개 문서를 일일이 탐색

❌ 비구조화된 자유 형식
   → 각 문서마다 작성 방식이 달라 일관성 없음
   → 데이터 추출 및 분석 불가능
   → 관계 정보가 텍스트 속에 숨어있음

❌ 시간적 맥락 부재
   → 사건들의 시간순 연결이 어려움
   → 과거-현재 인과관계 추적 불가능
   → 타임라인 시각화 없음

❌ 검색 기반 네비게이션
   → 우연히 찾은 정보만 습득
   → 전체 맥락 파악 어려움
   → "이 사건과 관련된 다른 사건은?" 답을 찾기 어려움
```

**뉴스 미디어/포털**
```
❌ 최신 정보만 제공
   → 역사적 배경 부재
   → "왜 이렇게 되었나?"에 대한 답 없음

❌ 단편적 보도
   → 개별 사건만 다룸
   → 복잡한 관계 설명 부족
```

**학술 데이터베이스**
```
❌ 전문가 전용
   → 일반인 접근 어려움
   → 비싼 구독료

❌ 검색 중심
   → 탐색 기능 부족
   → 시각화 미비
   
❌ 읽기만 가능
   → 내가 기여할 수 없음
   → 수동적 소비만 가능
```

**노션(Notion) 같은 범용 도구**
```
❌ 역사 도메인 특화 없음
   → 데이터 구조를 직접 설계해야 함
   → 사건, 인물, 국가 등의 템플릿 없음
   → 초기 셋업에 수십 시간 소요
   
❌ 제한적 시각화
   → 간단한 테이블/보드뷰만 지원
   → 관계 네트워크 그래프 없음
   → 타임라인 기능 약함
   → 교전국 관계도 같은 특화 기능 없음
   
❌ 수동적 관계 연결
   → 모든 관계를 일일이 수동으로 설정
   → 자동 연결 기능 없음
   → 멘션해도 단순 링크일 뿐
   
❌ 범용 도구의 한계
   → 역사 전문가가 설계한 구조 없음
   → 카테고리, 분류 체계 직접 구축
   → 결국 수백 시간 투자해도 불완전
   
❌ 협업/공유의 한계
   → 개인/소규모 팀용
   → 대규모 기관용 부적합
   → 데이터 표준화 어려움
   
비유:
  "노션으로 역사 DB 만들기 = 
   엑셀로 ERP 만들기"
   
  → 할 수는 있지만
  → 엄청난 시간과 노력 필요
  → 결과물이 불완전
  → 전문 시스템을 쓰는 게 답
```

#### 🎯 근본적 문제: **수동적 정보 소비**

```
기존 서비스들의 공통점:
  → 정보를 "보기만" 하는 수동적 경험
  → 내가 만들어가는 즐거움 없음
  → 지식 기여의 보람 없음
  
나무위키의 한계:
  → 자유 편집이지만 체계 없음
  → 내 기여가 다른 문서에 묻힘
  → 관계를 시각화해서 볼 수 없음
  → "내가 만든 지식 세계" 느낌 없음
  
AI의 한계:
  → 일방적 질문-답변 관계
  → 내가 데이터를 쌓을 수 없음
  → 내 지식이 휘발됨
  → 생산의 즐거움 없음
```

#### 🎮 사용자 경험(UX)의 근본적 차이

##### Papyrus의 핵심 가치: **능동적 지식 창조의 즐거움**

```
🌱 1. 데이터를 심는 즐거움
   "오늘은 어떤 역사를 기록할까?"
   
   → 사건 하나를 등록하면서
      • 관련 인물을 선택하고
      • 장소를 지정하고
      • 카테고리를 분류하고
      • 설명을 작성하는 과정
   
   → 마치 정원사가 식물을 심듯
      내 손으로 역사를 정리하는 보람

📊 2. 관계가 자라나는 즐거움
   "내가 입력한 정보가 자동으로 연결된다!"
   
   → 사건을 등록하면
      • 관련 사건이 자동으로 연결되고
      • 인물 페이지에 자동으로 추가되고
      • 타임라인에 자동으로 배치되고
      • 관계 그래프가 자동으로 확장됨
   
   → 내가 심은 데이터가
      살아 움직이는 지식 네트워크로 성장
   
   → "내가 한 작은 기여가 전체를 더 풍성하게!"

🎨 3. 시각화되는 즐거움
   "내가 만든 지식이 눈으로 보인다!"
   
   → 데이터를 입력할수록
      • 관계 그래프가 더 복잡하고 아름다워지고
      • 타임라인이 더 풍부해지고
      • 통계 차트가 더 의미있어짐
   
   → 마치 게임에서 레벨업하듯
      내 지식 세계가 성장하는 모습을 볼 수 있음

🤝 4. 공유하는 즐거움
   "내가 만든 지식을 다른 사람과 나눈다!"
   
   → 내가 정리한 역사 정보를
      • 학생들이 학습 자료로 활용
      • 연구자들이 연구 자료로 활용
      • 일반인들이 교양 자료로 활용
   
   → 내 기여가 누군가에게 도움이 되는 보람
   → 집단 지성의 일부가 되는 자부심

🏆 5. 전문가가 되는 즐거움
   "나도 이 분야의 전문가!"
   
   → 특정 주제에 집중하여
      • 관련 사건을 꼼꼼히 정리하고
      • 관계를 세밀하게 연결하면
   
   → 그 분야의 데이터베이스 구축자
   → "한국전쟁 전문가", "중동 분쟁 전문가" 등
      나만의 전문성 구축
```

##### 실제 사용 시나리오: "임진왜란을 정리한다면?"

**나무위키 방식:**
```
1. "임진왜란" 문서 편집
2. 긴 텍스트 작성
3. 관련 문서 링크 수동 추가
4. 저장
5. 끝... (내 기여가 어떻게 활용되는지 모름)

느낌: "문서 하나 수정했네..."
```

**AI 방식:**
```
1. "임진왜란에 대해 알려줘"
2. 답변 받기
3. 대화 종료
4. 내일 다시 물으면 처음부터...

느낌: "아무것도 남지 않았네..."
```

**Papyrus 방식:**
```
1. "임진왜란" 사건 등록
   → 시작일, 종료일, 장소 입력
   
2. 주요 전투들을 하위 사건으로 추가
   → 한산도 대첩, 명량 해전, 행주 대첩...
   → 각 전투가 타임라인에 자동 배치됨!
   
3. 관련 인물 선택
   → 이순신, 선조, 류성룡, 도요토미 히데요시...
   → 각 인물의 페이지에 자동으로 연결됨!
   
4. 교전국 설정
   → 조선 vs 일본 (명나라 지원)
   → 교전국 그래프가 자동 생성됨!
   
5. 결과 확인:
   ✨ 임진왜란 상세 페이지 완성
   ✨ 이순신 페이지에 모든 전투 자동 추가
   ✨ 조선-일본 관계 그래프 시각화
   ✨ 1592-1598 타임라인 완성
   ✨ 통계: 전투 12개, 인물 30명, 사상자 통계...

느낌: "와, 내가 임진왜란 데이터베이스를 만들었다!"
     "이제 학생들이 이걸 보고 배울 수 있겠네!"
     "다음엔 정유재란도 정리해봐야지!"
```

#### 기존 서비스별 한계 정리

- 📚 **정보 파편화**: 관련 정보가 수백 개 문서/페이지에 분산
- 🔍 **비구조화된 데이터**: 위키 등은 자유 형식으로, 체계적인 데이터 분석 불가
- 🌐 **관계 파악 어려움**: 사건-인물-국가-조직 간 복잡한 관계를 직관적으로 이해하기 어려움
- ⏰ **시간적 흐름 추적 곤란**: 역사적 사건의 원인과 결과를 시계열로 추적하기 어려움
- 🔗 **수동 연결의 한계**: 하이퍼링크만으로는 복잡한 관계 표현 불가능
- 🎓 **교육용 활용 제한**: 기존 자료는 교육/연구 목적의 체계적 활용에 한계
- 📊 **시각화 부재**: 텍스트 중심으로 복잡한 관계를 시각적으로 이해하기 어려움

#### Papyrus의 혁신적 해결 방안

##### 🎯 정보 파편화 완전 해결

**1. 통합 데이터베이스**
```
모든 정보를 하나의 시스템에 통합
  ✅ 사건 - 인물 - 국가 - 조직 모두 연결
  ✅ 한 곳에서 모든 관련 정보 조회
  ✅ "이 사건과 관련된 모든 것"을 즉시 표시
```

**2. 구조화된 데이터**
```
자유 형식이 아닌 체계적 구조
  ✅ 모든 사건이 동일한 형식으로 저장
  ✅ 관계 정보를 명시적으로 관리
  ✅ 검색, 필터링, 분석 가능
  ✅ API로 외부 서비스 연동
```

**3. 자동 관계 연결**
```
수동 링크가 아닌 자동 관계 맵
  ✅ 사건 등록 시 관련 인물/국가 자동 연결
  ✅ 멘션 시스템으로 즉시 연결
  ✅ 양방향 네비게이션
    - 사건 → 참여 인물
    - 인물 → 참여한 모든 사건
```

**4. 시각화**
```
텍스트가 아닌 그래프/차트로 이해
  ✅ 사건 관계 네트워크 그래프
  ✅ 타임라인 시각화
  ✅ 교전국 관계도
  ✅ 인물 관계도
  ✅ 통계 차트
```

**5. 시간적 맥락**
```
과거-현재를 하나로 연결
  ✅ 시계열 타임라인
  ✅ 인과관계 자동 표시
  ✅ 역사적 배경 자동 연결
  ✅ "왜 이렇게 되었나?"에 대한 답
```

**6. 통합 검색 & 탐색**
```
검색 + 탐색 + 발견
  ✅ 전역 검색으로 모든 엔티티 조회
  ✅ 관계 기반 탐색 (관련 사건 자동 추천)
  ✅ 카테고리/연도/국가별 필터
  ✅ "다음에 볼 것" 자동 제안
```

**나무위키/위키피디아의 문제:**
```
❌ 하나의 주제를 이해하려면 10~20개 문서 탐색 필요

❌ 정보의 신뢰도 판단 어려움 (누구나 편집 가능)
```

**AI (ChatGPT, Claude 등)의 문제:**
```
❌ 정보 파편화 미해결
   → 매번 새로운 대화 시작
   → 이전 대화 내용 재활용 어려움
   → 관계 정보가 휘발성

❌ 시각화 불가능
   → 텍스트 답변만 제공
   → 관계 그래프, 타임라인 없음
   → 복잡한 관계 이해 어려움

❌ 정보 신뢰성 문제
   → 환각(Hallucination) 현상
   → 출처 불명확
   → 사실 확인 어려움
   → 잘못된 정보 혼재

❌ 구조화된 데이터 없음
   → 답변이 매번 다름
   → 일관성 부족
   → 데이터베이스로 활용 불가

❌ 최신 정보 제한
   → 학습 데이터 시점 제한
   → 실시간 업데이트 불가 (무료 버전)
   → 유료 기능 필요

❌ 심층 분석 한계
   → 복잡한 관계 분석 약함
   → 다중 사건 간 연결 어려움
   → "전체를 보는 눈" 부족

❌ 교육/연구 활용 제한
   → API 비용 높음
   → 기관용 솔루션 부족
   → 커스터마이징 불가능
```

**뉴스/포털의 문제:**
```
❌ 최신 사건만 다룸 (역사적 맥락 없음)
❌ 자극적 헤드라인 중심
❌ 심층 분석 부족
```

##### Papyrus의 통합 솔루션

**vs 나무위키/위키피디아**
```
✅ All-in-One 통합 페이지
   예: "미중 무역전쟁" 단일 페이지에서
   - 사건 상세 정보
   - 배경 사건 (자동 연결)
   - 관련 인물 (트럼프, 시진핑 등)
   - 관련 국가 (미국, 중국)
   - 영향받은 산업/기업
   - 타임라인 (2018~현재)
   - 관련 뉴스/자료
   → 10~20개 문서 탐색 불필요!
```

**vs AI (ChatGPT, Claude 등)**
```
✅ 영구 저장된 구조화 데이터
   - 한 번 입력하면 영구 보관
   - 언제든 동일한 정보 조회
   - 대화 세션에 의존하지 않음
   → 정보 휘발 문제 해결!

✅ 강력한 시각화
   - 사건 관계 네트워크 그래프
   - 교전국 관계도
   - 인물 관계도
   - 타임라인 차트
   - 통계 대시보드
   → AI가 할 수 없는 시각적 분석!

✅ 검증된 정보 신뢰성
   - 전문가 검증 시스템
   - 출처 명시
   - 사실 확인 프로세스
   - 수정 이력 추적
   → 환각(Hallucination) 없음!

✅ 일관된 구조화 데이터
   - 모든 사건이 동일한 형식
   - 매번 같은 정보 제공
   - 데이터베이스 기반
   - API로 프로그래밍 접근
   → 기관/기업 활용 가능!

✅ 실시간 업데이트 (무료)
   - 최신 정보 즉시 반영
   - 관리자가 직접 업데이트
   - 유료 구독 불필요
   → 항상 최신 상태 유지!

✅ 복잡한 관계 자동 분석
   - 다중 사건 간 연결 자동화
   - 시간적 인과관계 추적
   - 전체 맥락 한눈에 파악
   - 패턴 분석 (향후 AI 결합)
   → 심층 분석의 새로운 차원!

✅ 교육/연구 특화
   - 기관용 맞춤 솔루션
   - 합리적 가격
   - 무제한 사용자
   - 커스터마이징 가능
   → 교육 현장에 최적화!

✅ 능동적 지식 창조 경험 🎯
   - 데이터를 입력하고
   - 관계가 자동 연결되고
   - 시각화가 실시간으로 생성되고
   - 내 기여가 쌓여가는 보람
   → AI는 줄 수 없는 창조의 즐거움!
```

**vs 나무위키 + AI 조합**
```
많은 사람들이 사용하는 방식:
  1. 나무위키에서 기본 정보 검색 (30분)
  2. AI에게 추가 질문 (20분)
  3. AI 답변의 사실 확인 (20분)
  4. 다시 나무위키로 돌아가서... (무한 반복)
  → 파편화 + 신뢰성 문제 동시에 발생

Papyrus:
  1. 단일 페이지에서 검증된 정보 조회 (10분)
  2. 관계 그래프로 전체 맥락 파악 (즉시)
  3. 타임라인으로 인과관계 이해 (즉시)
  → 효율 + 신뢰성 동시에 확보
```

```

   - 사건, 인물, 국가, 조직 등의 구조 사전 설계
   - 즉시 사용 가능한 템플릿
   - 초기 셋업 시간 제로

   - 교전국 관계 네트워크 그래프

   - 사상자 통계 차트
   - 인물 관계도
   → 노션의 단순 테이블 뷰와는 차원이 다름!

✅ 지능형 자동 연결
   - 멘션하면 양방향 자동 연결
   - 관련 사건 자동 추천
   - 타임라인 자동 배치
   - 관계 그래프 자동 업데이트
   → 수동 링크 설정 불필요!

✅ 도메인 지식 내장
   - 역사 전문가가 설계한 카테고리

   - 검증된 데이터 구조
   → 직접 설계하는 수백 시간 절약!

✅ 기관용 설계
   - 대규모 데이터 처리

비유:
  "노션 = 범용 스위스 칼
   Papyrus = 역사 전문가의 수술 도구"
   
  회사에서:
```

#### 🆕 현대 정보 관리 차별성

```
나무위키의 구조적 문제:

  ✅ 구조화된 데이터 → 일관된 정보
  ✅ 자동 관계 연결 → 즉시 탐색

  → 정보 접근 효율 **10~20배 향상**
```

##### vs AI (ChatGPT, Claude 등) - 🆕 핵심 경쟁자
```
AI의 구조적 한계:
  ❌ 대화 휘발성
    → 매번 새로운 대화 시작
    → 이전 내용 재활용 어려움

    → 관계도/타임라인 없음

    → 기관용 API 매우 비쌈
    → 토큰당 과금
    → 대규모 사용 시 수천만원
  
  예시: "미중 무역전쟁" 이해하기
    1. ChatGPT에 질문 (5분)

    3. 추가 질문 (5분)
    4. 또 사실 확인 (20분)
    5. 관계도는 직접 그려야 함 (30분)
    6. 내일 다시 물으면 처음부터 (무한 반복)

Papyrus의 솔루션:
  ✅ 영구 저장된 정보
    → 한 번 입력하면 영구 보관
    → 언제든 동일한 정보
    → 관계 데이터 지속 유지
  
  ✅ 100% 검증된 정보
    → 전문가 검증 시스템
    → 출처 명시
    → 환각 없음
    → 높은 신뢰성
  
  ✅ 강력한 시각화
    → 관계 네트워크 그래프
    → 타임라인 차트
    → 교전국 관계도
    → 즉시 이해 가능
  
  ✅ 완벽한 일관성
    → 항상 같은 정보
    → 구조화된 데이터
    → API로 프로그래밍 접근
  
  ✅ 합리적 비용
    → 기관 구독 월 99만원
    → 무제한 사용
    → AI 대비 1/10 비용
  
  예시: "미중 무역전쟁" 이해하기
    - 사건 페이지 열기 (1분)
    - 검증된 정보 확인 (즉시)
    - 관계 그래프 시각화 (즉시)
    - 타임라인 분석 (즉시)
    - 언제든 동일한 정보
    총 소요 시간: 10분 (+ 100% 신뢰 가능)
    
  → AI 대비 **효율 10배 + 신뢰성 확보**
```

##### vs 노션(Notion) 등 범용 도구 - 🆕 B2B 핵심 경쟁자
```
"노션으로 역사 DB를 만들 수 있지 않나요?"
→ 맞습니다. 하지만...

노션의 근본적 한계:
  ❌ 범용 도구 = 모든 걸 직접 설계
    → 사건, 인물, 국가의 데이터 구조 설계 (2주)
    → 카테고리, 속성 필드 정의 (1주)
    → 관계 설정 방식 고민 (1주)
    → 템플릿 제작 (1주)
    → 총 1개월 셋업 시간
  
  ❌ 제한적 시각화
    → 테이블, 보드, 갤러리뷰만
    → 관계 네트워크 그래프 없음
    → 복잡한 교전국 관계도 불가능
    → 시계열 타임라인 약함
  
  ❌ 수동 관계 연결
    → 사건-인물 연결을 일일이 수동 설정
    → 자동 업데이트 없음
    → 양방향 연결 보장 안됨
    → 관계가 복잡해지면 관리 불가
  
  ❌ 범용 도구의 딜레마
    → 자유도 높음 = 책임도 높음
    → 잘못 설계하면 나중에 수정 지옥
    → 표준화 어려움
    → 다른 사람이 이어받기 어려움
  
  실제 사례:
    - 어떤 대학이 노션으로 역사 DB 구축 시도
    - 3개월 작업 후 포기
    - 이유: "너무 복잡해서 유지보수 불가능"

Papyrus의 솔루션:
  ✅ 도메인 전문가가 이미 설계
    → 사건, 인물, 국가 구조 완성
    → 역사학자들이 검증한 카테고리
    → 즉시 사용 가능
    → 셋업 시간 0분
  
  ✅ 전문화된 시각화
    → 교전국 네트워크 그래프
    → 역사 전용 타임라인
    → 사상자 통계 차트
    → 인물 관계도
    → 노션이 절대 못하는 것들
  
  ✅ 지능형 자동 연결
    → 멘션하면 모든 관계 자동 연결
    → 타임라인 자동 배치
    → 통계 자동 계산
    → 관계 그래프 실시간 업데이트
  
  ✅ 표준화된 시스템
    → 누가 입력해도 일관성 유지
    → 인수인계 쉬움
    → 기관 간 데이터 공유 가능
  
  비교:
    노션으로 역사 DB 만들기 = 엑셀로 ERP 만들기
      → 할 수는 있지만
      → 시간 낭비 + 불완전한 결과
      → 전문 시스템 쓰는 게 답
    
  시간 비교:
    - 노션: 셋업 1개월 + 지속적 관리 부담
    - Papyrus: 셋업 0분 + 자동 관리

  → Papyrus는 기관/전문가용
```

#### 독창적 기능

##### 🎯 교전국 그래프 (Belligerents Graph)
```
전쟁/분쟁의 복잡한 동맹 관계를 네트워크 그래프로 시각화
- 자동 배치 알고리즘
- 양측(편) 구분
- 인터랙티브 탐색

예: 제2차 세계대전
  [연합국]─────────[추축국]
     │                 │
  미국, 영국        독일, 일본
  소련, 프랑스      이탈리아
```

##### 🎯 멘션 시스템
```
사건 설명에서 @인물, #조직 자동 태그
→ 자동으로 관계 데이터베이스 구축
→ "이 인물이 참여한 모든 사건" 즉시 조회
```

##### 🎯 역사-현대 국가 연결
```
과거 국가와 현재 국가를 체계적으로 연결
예:
  조선 → 대한민국
  페르시아 제국 → 이란
  로마 제국 → 이탈리아
```

##### 🎯 능동적 지식 창조 경험 (Papyrus만의 독창성)
```
단순 정보 소비가 아닌 지식 생산의 즐거움

1. 입력의 즐거움
   → 사건, 인물, 관계를 내 손으로 정리
   → 체계적 구조 속에서 데이터 쌓기
   
2. 성장의 즐거움
   → 데이터를 입력할수록
   → 관계 그래프가 확장되고
   → 타임라인이 풍부해지고
   → 내 지식 세계가 시각적으로 성장
   
3. 공유의 즐거움
   → 내가 정리한 정보를
   → 다른 사용자들이 활용
   → 집단 지성에 기여하는 보람
   
4. 전문성의 즐거움
   → 특정 주제에 집중하면
   → 그 분야의 전문 DB 구축자가 됨
   → "한국전쟁 전문가", "프랑스 혁명 전문가"
   
💡 이것은 나무위키의 "편집"도, AI의 "대화"도 줄 수 없는
   Papyrus만의 독창적 경험입니다.
   
비유:
  - 나무위키 = 위키백과 편집 (문서 하나 수정)
  - AI = 선생님께 질문 (휘발성 대화)
  - Papyrus = 내 정원 가꾸기 (지식 세계 구축)
```

### 6.3 진입 장벽

#### 기술적 진입 장벽
- 복잡한 도메인 모델링 (3년 이상 소요)
- 엔터프라이즈 아키텍처 구축 노하우
- 대규모 역사 데이터 정제 및 구조화

#### 데이터 진입 장벽
- 구조화된 역사 데이터베이스 구축
- 품질 검증된 데이터
- 지속적인 데이터 업데이트 체계

#### 경험 진입 장벽 (핵심) 🆕
```
"데이터를 쌓아가는 즐거움"을 설계하는 것은
단순한 기능 개발보다 훨씬 어렵습니다.

1. 심리적 보상 설계
   → 사용자가 데이터를 입력할 때마다
   → 즉각적인 시각적 피드백
   → "내가 무언가를 만들어가고 있다"는 느낌
   → 이것을 구현하는 것은 고도의 UX 설계 필요

2. 관계 자동 연결의 마법
   → 사용자가 입력하면
   → 자동으로 모든 관계가 연결되는 시스템
   → 이것은 복잡한 데이터 모델링과 알고리즘 필요
   → 단순 DB 구축과는 차원이 다름

3. 시각화의 즉시성
   → 데이터 입력 즉시 그래프가 업데이트
   → 실시간 렌더링 최적화
   → 수천, 수만 개 노드 처리
   → 고성능 시각화 엔진 필요

4. 심리적 동기 유지
   → 사용자가 계속 데이터를 입력하게 만드는 것
   → 게이미피케이션 요소
   → 진행도 표시, 성취 시스템
   → "다음에 뭘 입력할까?" 유도 설계

→ 이것은 기술 + 심리학 + UX 설계의 종합체
→ 단순 복사로는 절대 따라올 수 없음
```

### 왜 Papyrus인가?

#### 현재 사람들의 정보 탐색 방식과 문제
```
"미중 무역전쟁을 이해하려면?"

방법 1: 나무위키 사용
  → 20개 문서를 2시간 동안 탐색
  → 파편화된 정보, 전체 맥락 파악 어려움
  → 수동적 소비만 가능
  
방법 2: AI (ChatGPT) 사용
  → 질문하고 답변 받기 (빠름)
  → 하지만 사실 확인 필요 (신뢰성 의심)
  → 시각화 불가능, 대화 내용 휘발
  → 일방적 질의응답
  
방법 3: 노션으로 정리 (기관/전문가)
  → 데이터 구조부터 설계 (1개월)
  → 수동으로 관계 연결 (지속적 부담)
  → 시각화 한계, 유지보수 어려움
  → 결국 포기하거나 불완전
  
방법 4: 나무위키 + AI 병행 (일반인)
  → 나무위키에서 검색 → AI에 질문 
  → AI 답변 확인 → 다시 나무위키 
  → 반복... 3~5시간 소요
  → 여전히 피로하고 불확실함
  → 아무것도 남지 않음
```

#### Papyrus의 혁신적 해결책
```
단 하나의 페이지에서 10분 만에
  ✅ 검증된 모든 관련 정보
  ✅ 역사적 맥락 자동 연결
  ✅ 관계 그래프 시각화
  ✅ 타임라인 인과관계
  
그리고 가장 중요한 것:
  🎯 내 손으로 직접 만들어가는 즐거움
  💼 전문가가 설계한 시스템 (셋업 0분)
  
→ 나무위키의 파편화 해결
→ AI의 불확실성과 휘발성 해결
→ 노션의 복잡성과 한계 해결
→ 수동적 소비를 능동적 창조로 전환!
```

```
"단순히 정보를 찾는 것이 아니라,
 내가 지식을 만들어가는 경험"

1. 데이터를 입력하면
   → 관계가 자동으로 연결되고
   
2. 관계 그래프가 실시간으로 확장되고
   → 시각화되는 모습을 보며
   
3. 타임라인이 풍부해지고
   → 내 지식 세계가 성장하는 것을 느끼고
   
4. 다른 사람들이 내 데이터를 활용하고
   → 창조의 보람을 느낍니다

이것은:
  ❌ 나무위키의 "문서 편집"이 아닙니다
  ❌ AI의 "질문-답변"도 아닙니다
  ✅ 마치 내 정원을 가꾸듯
     나만의 지식 세계를 구축하는 것입니다
     
비유:
  - 나무위키 = 도서관 책 한 권 수정
  - AI = 선생님께 질문
  - Papyrus = 내 박물관 만들기 🏛️
```

```
      일시적 정보 → 영구적 지식 축적
      혼자 보기 → 함께 나누기

→ 이것이 Papyrus가 해결하는 핵심 문제입니다.
→ 정보 파편화와 불확실성의 시대를 끝내고,
   통합되고 신뢰할 수 있는 지식의 시대를 열며,
→ 수동적 소비의 시대를 끝내고,
   능동적 창조와 공유의 시대를 엽니다.
```
