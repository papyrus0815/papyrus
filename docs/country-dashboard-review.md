## 0. 요약 — 근인 3축

이 지면은 **잘 만들어진 부품이 잘못된 모수 위에 놓여 있다.** 개별 패널(정권 슬라이더,
완성도 도넛, 대륙 비교, 피라미드)은 각자 완성도가 높은데, 첫 화면이 주는 인상은
"넓고 비어 있다"이다. 원인은 세 가지다.

**① 폭이 흡수되지 않는다.**
본문에 측정폭 상한이 없어 2,992px 화면에서 본문이 **2,202px**가 된다. 그 결과
`기록` 카드 한 장이 **710×178px**인데 담는 값은 `0` 한 글자, 정권 캐러셀 화살표는
카드에서 **1,600px 떨어진 곳**에 떠 있고, 히어로는 **2,202×168px**의 빈 띠다.
사건 목록에서 이미 겪고 `LIST_STEPS` 열 사다리로 해결한 것과 **같은 병**이다.

**② 화면의 모수가 실데이터와 어긋난다.**
대시보드는 "자료가 풍부한 나라"를 가정하고 6칸 격자 + 차트 2섹션을 **고정 배치**한다.
실제 DB는 그렇지 않다 — 조약 0행(전 국가), 군대 0행, 행정구역 2국, 선거 1국,
인구 피라미드 1국, 경제지표 0행, 사건 0건 43국(61%), 인물 0명 41국(58%).
그래서 대부분의 국가에서 첫 화면 절반이 **큼직한 `0`**이고, 페이지 끝은
"등록된 …이 없습니다" **2연발**로 끝난다.

**③ 시각 언어가 한 지면에 3벌이다.**
대시보드 자체 액센트 6색(indigo/violet/rose/amber/sky/emerald) + 피라미드 남녀
`#3b82f6`/`#ec4899` + 지표 차트 구글 팔레트(`#4285f4`/`#34a853`)와 **하드코딩 라이트
톤**(그리드 `#e5e7eb`, 흰 툴팁). 아이콘도 SVG 세트와 이모지(📈 👥)가 섞인다.

부수 축 하나 더: **국가 정체성 자산이 화면에 없다.** 썸네일 보유 2/71인데
`flag_emoji`는 **71/71** 다 있고, 히어로는 그걸 쓰지 않는다.

### 1-3. 진입 시 쿼리

대시보드 1회 진입에 **약 17개 요청**이 뜬다(stats 훅 11 + 정권 패널 4~5 + 지표 2).
이 중 **3쌍이 같은 엔드포인트를 다른 캐시 키로 두 번** 부른다.

| 데이터 | stats 훅 키 | 정권 패널 키 |

| 선거 | `['elections-by-country', id]` | `['elections','by-country',id]` |
| 부처 | `['administration-departments-by-country', id]` | `['administration-departments','by-country',id]` |

## 7. 교역 품목 — 스키마부터 화면까지 (2026-09-05)

§6에서 "무엇을 수출·수입하는가"에 답할 수 없다고 적었던 칸을 채웠다.

### 스키마

`libs/db/prisma/country.prisma` — 마이그레이션 `20260905171706_add_export_import_item`

```prisma
enum TradeDirection { EXPORT IMPORT }

model ExportImportItem {
  exportImportId   String          // 부모 = 그 국가의 그 해
  direction        TradeDirection
  name             String          // 반도체, 승용차, 원유
  hsCode           String?         // 국제 분류 대조용
  value            Decimal?        // 금액
  sharePct         Decimal?        // 그 방향 총액 중 비중(%)
  partnerCountryId String?         // 교역 상대국 (Country, SetNull)
  sortOrder        Int
}
```

금액과 비중을 **둘 다 선택 항목**으로 둔 이유: 실제 교역 자료는 "반도체 20.4%"처럼 비중만
아는 경우와 금액만 아는 경우가 반반이다. 하나를 필수로 만들면 아는 것도 못 넣는다.
부모 삭제는 CASCADE — 그 해를 지우면 그 해 품목도 함께 지워진다(실측 확인).

### API

- `GET /countries/:id/export-imports` 응답에 `items[]` 포함 (direction → sortOrder → name 순).
  `partnerCountryName`을 함께 내려 프론트가 국가 목록을 다시 조회하지 않게 한다.
- `POST` 입력에 `items?` 추가. **`undefined`면 품목을 건드리지 않고**, 배열이면 그 해 품목을
  통째로 교체한다(delete-and-recreate, 기업 `CompanyProduct`와 같은 규약). 총액만 고치는
  기존 호출이 품목을 조용히 날리면 안 되기 때문이다. 빈 배열은 명시적인 '전부 지우기'.
- 총액 upsert와 품목 교체는 **한 트랜잭션**이다 — 품목 교체가 실패했는데 총액만 바뀌면
  "수출 6.8조인데 품목은 작년 것"이 남는다.

### 화면

- 데이터 관리 → 교역 탭: 방향·품목명·금액·비중·HS·상대국 행 편집 + `+ 수출 품목`/`+ 수입 품목`.
  품목을 손대지 않은 저장은 `items`를 보내지 않는다(매번 보내면 내용이 같아도 행 id가 갈린다).
  품목명이 빈 줄은 저장하지 않고 그 사실을 토스트로 알린다.
- 대시보드 교역 섹션: 총액·무역수지 아래에 `수출 품목` / `수입 품목` 두 줄. 비중이 있으면
  비중을, 없으면 금액을 붙이고, 상대국이 있으면 `→ 미국`을 덧붙인다.

### 검증

tsc 0(api·web) · 변경 파일 신규 lint 0 · api jest 168 통과 · web jest 883 통과
(양쪽의 기존 실패 스위트는 손대지 않은 파일 — gamification `badge.policy`, rich-text 등).

실화면 왕복: 한국 2024년에 수출 반도체 20.4%(→미국)·승용차 11.2%, 수입 원유 12.8%을 넣어
대시보드 표시까지 확인하고, **총액만 수정 저장했을 때 품목 3개가 그대로 남는 것**(items
undefined 계약)과 연도 삭제 시 품목까지 CASCADE 되는 것을 확인한 뒤 **테스트 데이터를
삭제했다**(export_import·export_import_item 모두 0행).

## 8. 행정부 마인드맵 (2026-09-05)

근거: 예전 배치는 "이 정권에 이런 사람들이 있다"는 **목록**은 됐지만 "이 사람 밑에 이

- 연결선은 **JS 실측 없이 CSS만으로** 그린다. 가계도에서 상수 폭과 실제 DOM 폭이 어긋나
  선이 빗나갔던 전례가 있어, 노드 높이를 46px로 고정하고 척추선을 그 절반(23px)만큼

  한가운데를 비껴간다.
- 1,100px 미만에서는 한 칼럼으로 접히고 가운데 노드가 위로 간다(좌→우 순서 보존).
- 죽은 styled 21개(`Hero*`·`Roster`·`MemberCard`…)와 `visible` 제거 → 패널 2,470 → 2,186줄.

### 디자인 2차 — 직각에서 곡선으로

첫 판은 직각 브래킷이었다. 직각으로 꺾으면 **조직도**가 되고, 조직도는 지휘계통을
주장한다 — 여기 있는 건 "이 정권을 이룬 사람들"이지 명령 체계가 아니다.

- 가지를 **베지어 곡선**으로 바꿨다. 곡선에는 좌표가 필요하고 좌표를 얻는 길은
  DOM 실측이거나 고정 규격이거나 둘뿐인데, 실측은 가계도에서 이미 어긋나 봤다.
  그래서 **규격을 고정**했다 — 노드 높이 46 · 간격 12 · 거터 64 · 가지 칸 236px.
  i번째 노드의 중심 y가 산술로 나오므로 곡선을 계산 없이 정확히 그린다.
  SVG를 칼럼이 아니라 **노드 묶음**에 붙이는 게 핵심이다(칼럼은 행 높이만큼 늘어나
  그 안에서 묶음 위치를 알 수 없다). 실측 검증: 곡선 수렴점과 카드 모서리 간격 0px,
  부채꼴 원점 y와 카드 중심 y가 동일.
- 요약(취임·재임·각료·교체·득표율)을 카드 **안**으로 넣었다. 밖에 두면 가운데 칸이
  카드보다 커져 곡선이 카드 모서리가 아니라 허공에서 끝난다.
- 얼굴에 링, 카드에 그라데이션·그림자. 임기 중 교체된 자리는 색을 칠하지 않고
  가장자리 한 줄(amber)로만 표시한다.
- 요약 줄바꿈은 격자(auto-fit) 대신 flex — 격자는 마지막 줄이 칸 수를 물려받아
  두 칸이 세 칸 폭에 늘어붙어 첫 줄과 어긋났다.

검증: tsc 0 · 변경 파일 lint 0 · jest 883 통과 · 실화면 미국(각료 15)·독일/러시아(각료 0)
× 다크/라이트 + DOM 좌표 실측.

### 디자인 3차 — 얼굴을 키우고, 선거를 지도 안으로

- **얼굴 부각**: 가운데 92 → **112px**(링 3px + 글로우), 가지 노드 28 → **36px**
  (노드 높이 46 → 54, 곡선 좌표가 상수 기반이라 자동으로 따라온다), 정권 슬라이더
  40 → **48px**. 선거 당선자 행에도 얼굴을 붙였다 — 다만 선거 상세 응답의 후보에는
  `profileImageUrl`이 없어, **수반과 같은 인물일 때만** 지도 한가운데의 얼굴을 재사용한다.
  (후보 전원의 얼굴을 그리려면 선거 상세 DTO에 이미지 필드를 더해야 한다)
- **행정부 ↔ 선거**: 선거 패널을 폭 전체를 가로지르는 납작한 띠에서 떼어 내
  지도의 **아래 줄기**로 달았다. 좌우 가지는 곡선(여럿으로 갈라짐), 아래 줄기는
  직선(하나에서 하나로) — 선거는 이 정권 하나를 낳았다.
- 정권 슬라이더·부처별 우두머리·최근 선거까지 **같은 축(640px)** 에 세웠다.
  한 덩어리로 읽히지 않으면 마인드맵이 지면 위에 떠 있는 삽화가 된다.

검증: tsc 0 · lint 0 · jest 883 · 미국/독일 × 다크·라이트.
