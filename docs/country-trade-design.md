# 국가 교역(수출·수입) 기록 설계

> 2026-09-05 · 브랜치 `feature/service-manager-v2`

## 출발점

기존 교역 기능은 `export_import` 한 테이블에 **연도·수출총액·수입총액** 셋뿐이었다.
"얼마나"에는 답해도 **무엇을·누구와·어떻게**에는 답하지 못했고, 현대 국가 71곳만
주체가 될 수 있어 역사 국가 282곳의 교역은 담을 자리가 없었다. 실제 데이터도 0행이었다.

## 세 겹 구조

```
품목 카탈로그                 연도 헤더                      교역 흐름
TradeCommodityCategory   →   ExportImport              →   ExportImportItem
TradeCommodity               (주체·연도·총액·통화·출처)      (무엇을·누구와·얼마나·어떻게)
```

### 1. 품목 카탈로그 — "석유"는 한 행이다

`석유 / 원유 / crude oil / 石油`처럼 자료마다 표기가 갈린다. 나라·연도마다 문자열을
다시 치면 같은 물건이 수십 행으로 흩어지고, **"1913년에 강철을 수출한 나라"** 같은
가로 질문이 아예 성립하지 않는다.

- `TradeCommodityCategory` — 대분류 > 중분류 계층, HS 부(section) 대조, 색·이모지
- `TradeCommodity` — 이름·영문명·**별칭(검색용)**·HS/SITC 코드·기본 수량 단위·
  **존재 구간**(자동차를 1700년 수출로 적는 실수를 폼에서 잡는다)·서비스 여부

시드: 분류 45개(대분류 15 + 중분류 30), 품목 125개.
근대 이전 품목(비단·후추·아편·초석·구아노·모피·인삼·조공품)과 현대 품목
(반도체·LNG선·이차전지·희토류)을 함께 담았다.

카탈로그에 없는 품목은 **자유 입력**으로 그대로 적을 수 있고(사료의 `生絲`·`白木`),
분류만 따로 걸 수 있다. 나중에 카탈로그로 승격하면 된다.

### 2. 연도 헤더 — 금액에는 단위가 붙는다

옛 스키마의 `exportValue`에는 **통화도 자릿수도 없었다**. 6.8이 파운드인지 달러인지,
백만인지 억인지 모르는 숫자는 다른 해·다른 나라와 비교할 수 없다.

| 추가 | 이유 |
|---|---|
| `countryId` \| `historicalCountryId` | 조선·청·한자동맹도 주체가 된다 (dual-fill 규약) |
| `era` + `year` | 기원전 교역(로마–한나라)도 기록 가능 |
| `periodEndYear` + `aggregation` | "1860년대 연평균" 같은 기간 자료 |
| `currencyCode` + `valueScale` | 원자료 그대로 넣고 단위를 옆에 적는다 |
| `priceBasis` (FOB/CIF) | 같은 무역도 수출국 장부와 수입국 장부에서 값이 다르다 |
| `priceNote` | "1913년 불변가격" |
| `sourceName` / `sourceUrl` / `isEstimate` / `confidence` | 근대 이전 통계는 추계마다 갈린다 |

### 3. 교역 흐름 — 무엇을 · 누구와 · 어떻게

한 행이 **어느 단면(grain)**인지 스스로 밝힌다. 단면이 다른 행을 더하면 같은 무역을
두 번 세기 때문이다.

- `COMMODITY` — 품목별 ("수출의 24%가 면직물")
- `PARTNER` — 상대국별 ("수출의 12%가 인도로")
- `PARTNER_COMMODITY` — 둘을 함께 특정

**상대는 넷 중 하나**: 현대 국가 · 역사 국가 · 조직(동인도회사·한자동맹·EU) · 자유 표기
("기타 유럽", "세계 전체"). 둘 이상 걸면 서버가 400으로 막는다.

**얼마나**: 금액 · 비중(%) · 수량 + 단위 · 단가 · 가격기준 · 순위 · 전년비
— 금액 없이 수량만 남은 자료(면화 몇 담, 배 몇 척)가 많아 어느 하나만 있어도 저장된다.

**어떻게** — 자유무역만 있는 게 아니다:

| 칸 | 담는 것 |
|---|---|
| `channel` | 공무역 · **조공무역** · 사무역 · **밀무역** · 개항장/조계 · 특허회사 독점 · 국가 전매 · 원조 · 바터 |
| `restriction` | 금수 · 제재 · 쿼터 · 금지품목 · 허가제 · 보호관세 · 반덤핑 |
| `tariffRatePct` | 관세율 |
| `isReExport` | 홍콩·싱가포르 중계무역 (자국 수출로 세면 안 된다) |
| `transportMode` | 해상 · 하천 · 육상 · **대상(隊商)** · 철도 · 항공 · 파이프라인 · 해저케이블 |
| `routeName` / `portName` | 실크로드·희망봉 항로 / 광저우·부산 왜관·나가사키 데지마 |

**왜** — 그 교역을 만든 것: `relatedEventId`(아편전쟁) · `relatedTreatyId`(강화도조약) ·
`relatedCompanyId`(동인도회사).

## API

| 경로 | 역할 |
|---|---|
| `GET/POST/PUT/DELETE /trade/commodity-categories` | 분류 CRUD (품목이 붙어 있으면 삭제 차단) |
| `GET/POST/PUT/DELETE /trade/commodities` | 품목 CRUD, `q`는 이름·영문·별칭·HS를 함께 훑는다 |
| `GET /trade/commodities/:id/flows` | **품목으로 가로줄 읽기** — 누가·언제·누구와 |
| `GET/POST/DELETE /trade/records` | 현대·역사 국가 공용 교역 기록 |
| `GET/POST/DELETE /countries/:id/export-imports` | 기존 창구 유지 (응답 모양 동일) |

`GET /trade/records?countryId=`는 브리지로 연결된 **역사 국가의 교역까지** 함께 준다
(정체·법령·사건과 같은 스코프 규약) — 대한민국을 열면 대한제국·조선의 교역이 한 시간축에 놓인다.

## 화면

- **편집** (`trade-panel`): 연도 헤더 + 흐름 카드. 흐름은 칸이 25개 가까이 되지만 자료에
  다 있는 경우는 드물어 **늘 보이는 6칸 + 접이식 상세**로 갈랐다. 품목 입력은 카탈로그
  125종을 제안하되 자유 입력을 막지 않는다. **비중 합 점검 줄**이 100%를 넘으면 경고한다.
- **조회** (`trade-section`): 총액 → **분류 구성 막대**(원유·석탄이 따로 놓이면 '에너지 60%'라는
  한눈이 사라진다) → 품목·상대 칩. 추정치·출처를 아래 한 줄로 밝힌다.
- 역사 국가 상세에 **교역 탭** 신설.

## 남은 것

- 흐름의 `relatedEvent`/`relatedTreaty`/`relatedCompany` 선택 UI (스키마·API·응답은 완비,
  편집 폼에는 아직 칸이 없다)
- 조직(Organization) 상대 선택 — 패널이 목록을 아직 안 받아 온다(빈 배열 전달)
- 여러 해를 겹쳐 보는 시계열 차트, 품목 가로줄(`/trade/commodities/:id/flows`) 전용 지면
- 실제 교역 데이터 시드 (현재 카탈로그만 있고 기록은 0행)
