# 역사적 국가(HistoricalCountry) 설계 평가 — 막부·시대 표현 적합성

## 1. 현재 설계 요약

- **HistoricalCountry**: 이름, 국가 형태(HistoricalStateType), 존속 기간, 현대 국가와의 연결, 변천(Transition)·소속(Membership)·관계(Relation).
- 재임(Tenure)·행정부(Cabinet)는 `countryId`(현대) 또는 `historicalCountryId`(역사적)로 **한 정치체**에 소속.

---

## 2. 적합성 평가

### 2.1 잘 맞는 부분

| 용도 | 적합성 | 비고 |
|------|--------|------|
| **과거 주권 국가** (신성로마제국, 프로이센, 브란덴부르크) | ✅ 적합 | “역사적 국가”라는 이름·의미와 일치. stateType(제국/공국/변경백령)으로 구분 가능. |
| **동일 공간의 정권·시대** (무로마치/에도/메이지) | ⚠️ 사용 가능하나 의미 확장 | 재임·행정부를 “그 시대/정권”에 묶는 용도로는 **동작**함. 다만 개념이 “국가”가 아니라 “정권/시대”. |
| **변천·소속·관계** | ✅ 적합 | 무로마치→에도→메이지, 신성로마↔제후국 등 관계 표현에 유리. |

### 2.2 부족한 부분

1. **용어·개념 혼재**
   - “역사적 **국가**”는 주권 국가 단위에 맞는 말.
   - 무로마치 막부·에도 막부는 **정권(군정)** 이지, 일본이란 국가가 바뀐 것이 아님.
   - 메이지 시대는 **시대(기간)** 구분에 가깝다.
   - 같은 테이블에 “제국/공국”과 “막부/시대”가 함께 들어가 있어, **역할**이 구분되지 않음.

2. **국가 형태(HistoricalStateType)**
   - 막부에 해당하는 값이 없음. `HEREDITARY`, `OTHER`로만 표현 가능.
   - “모든 막부만 조회” 같은 질의가 타입만으로는 불가능.

3. **미래 확장**
   - 다이쇼·쇼와 등 “시대”를 더 넣으면, “역사적 국가” 행이 계속 늘어나며 이름과 실제 의미(시대/정권) 괴리가 커짐.
   - “이건 주권 국가”, “이건 한 나라의 정권/시대”를 **구분**할 수 있으면, 통계·필터·UI 라벨을 더 정확히 할 수 있음.

---

## 3. 결론: “최적·미래지향”인가?

- **동작 측면**: 무로마치/에도/메이지를 각각 HistoricalCountry 1건으로 두고, 재임·행정부를 거기에 묶는 현재 방식은 **가능하고 실용적**.
- **개념·확장 측면**: “역사적 국가” 한 종류로 **주권 국가 + 정권 + 시대**를 모두 표현하고 있어, **완전히 최적·미래지향이라고 보기는 어렵다**. 특히:
  - “국가 vs 정권 vs 시대” 구분이 없고,
  - 막부 같은 형태가 타입에 없으며,
  - 용어가 “국가”로 고정되어 있어, 정권/시대를 넣을수록 의미가 흐려짐.

따라서 **지금도 쓰기는 적합**하지만, **의미를 나누고 막부·시대를 더 잘 표현하려면** 아래처럼 소폭 보완하는 편이 좋다.

---

## 4. 권장 개선안 (호환 유지)

### 4.1 정치체 구분(entityKind) 추가

**의도**: 같은 테이블을 유지하면서 “주권 국가 / 정권 / 시대”를 구분.

| 필드 | 타입 | 설명 |
|------|------|------|
| `entityKind` | enum (nullable) | `STATE`(주권 국가) / `REGIME`(정권·군정) / `PERIOD`(시대) |

- **STATE**: 신성로마제국, 프로이센, 브란덴부르크, 고려, 신라 등.
- **REGIME**: 무로마치 막부, 에도 막부 등 (한 국가 안의 군정/정권).
- **PERIOD**: 메이지 시대, 다이쇼 시대 등 (연호·시대 구간).

- 기본값: `null` 또는 `STATE` (기존 데이터는 “과거 주권 국가”로 해석).
- UI/통계에서 “역사적 국가 / 정권 / 시대” 필터·라벨에 사용 가능.

**설계상 논의: "시대"(PERIOD)와 정치체**

- **시대**는 정치체가 아니라 **기간 구분**(연호·시대 구간)에 가깝다. 따라서 "정치체 성격 = 시대"는 개념상 어색하다는 지적이 있다.
- 현재는 연호·기간 단위를 같은 테이블(HistoricalCountry)에서 구분하기 위한 **실용적 레이블**로 PERIOD를 쓰고 있다.
- 추후 "기간/연호" 전용 모델로 분리하거나, entityKind에서 PERIOD를 빼고 기간만 별도 관리하는 방안을 검토할 수 있다.

### 4.2 국가 형태에 SHOGUNATE 추가

**의도**: 막부를 타입으로 표현해 조회·필터 용이.

- `HistoricalStateType`에 **SHOGUNATE**(막부) 추가.
- 무로마치·에도 막부는 `stateType = SHOGUNATE`, `entityKind = REGIME` (또는 REGIME만)으로 저장.

### 4.3 UI/용어 정리 (선택)

- 노출용 라벨을 **“역사적 정치체”** 또는 **“과거 정치체(국가·정권·시대)”** 로 바꾸면, 막부·시대를 넣어도 의미가 더 명확해짐.
- 상세/목록에서 `entityKind` 값에 따라 “국가 / 정권 / 시대” 뱃지 표시 가능.

## 5. 대안(구조 변경)과 비교

| 방안 | 장점 | 단점 |
|------|------|------|
| **현상 유지** | 변경 없음 | 개념 혼재·막부 타입 부재는 그대로. |
| **entityKind + SHOGUNATE (권장)** | 최소 변경, 기존 데이터 호환, 막부·시대·국가 구분 가능 | enum/필드 추가와 UI 반영 필요. |
| **Period/Regime 테이블 분리** | “국가”와 “시대/정권”이 완전히 분리됨 | 스키마·API·UI 전반 변경, 마이그레이션 부담. |

현 단계에서는 **4.1 + 4.2** 정도의 최소 개선이, 무로마치/에도/메이지 등을 **현실적으로 잘 표현하면서도 미래지향적으로 정리**하는 방향에 가깝다고 볼 수 있다.

## 6. 구현 완료 사항 (적용된 개선)

### 6.1 스키마 (libs/db/prisma/historical.prisma)

- **HistoricalEntityKind** enum: `STATE` | `REGIME` | `PERIOD`
- **HistoricalCountry.entityKind**: nullable, 정치체 성격 구분
- **HistoricalStateType**: **SHOGUNATE**(막부) 추가
- **TransitionScope** enum: `STATE_SUCCESSION`(국가 계승) | `REGIME_CHANGE`(정권 교체)
- **HistoricalCountryTransition.transitionScope**: nullable, 전환의 성격 구분

### 6.2 API

- 목록 조회: 쿼리 파라미터 `entityKind`, `stateType` 지원
- 생성/수정 DTO·응답: `entityKind` 포함
- 계승/변천 생성·수정·응답: `transitionScope` 포함
- Repository: `findAll(accountId, filter)` 에서 entityKind/stateType 필터

### 6.3 웹 UI

- 목록: entityKind 뱃지(국가/정권/시대), stateType에 막부(SHOGUNATE) 표시
- 상세: 정치체 성격 뱃지, 국가 형태에 막부 반영
- 폼: 정치체 성격 선택(미지정/주권 국가/정권·군정/시대), 국가 형태 옵션에 **막부** 추가
- 필터: 성격(전체/국가/정권/시대) 필터 버튼 및 모달
- 빈 상태 문구: "과거 정치체", "국가·정권·시대를 추가해보세요"

### 6.4 용어

- 화면에서 "역사적 국가"와 함께 "과거 정치체", "국가·정권·시대" 표현 사용 (목록 빈 상태 등)

## 7. 추가 고려 사항 (적용 완료)

- **검증/가이드**: ✅ REGIME 선택 시 폼에 "정권·군정인 경우 국가 형태에 **막부**를 선택하는 것을 권장합니다" 힌트 표시.
- **통계**: ✅ 대시보드에 **정치체 성격별 분포**(국가/정권/시대/미지정) 섹션 추가.
- **전환 성격**: ✅ 역사적 국가 폼에서 후임 국가 선택 시 **전환 성격**(국가 계승 / 정권 교체) 선택 필드 추가. API·저장 시 transitionScope 반영. 연결된 역사적 국가 섹션에서 변천 표시 시 transitionScope 라벨 표시.
- **기존 데이터**: entityKind·transitionScope는 nullable이므로 기존 행은 그대로 두고, 필요 시 단계적으로 보정하면 됨.

## 9. 일본 역사적 국가 구분 가이드

일본은 “한 국가(일본)”가 유지된 채 **정권(막부)**·**시대(연호)**만 바뀌므로, 아래처럼 **entityKind**와 **stateType**을 나누어 등록하면 된다.

| 구분 | 이름 예시 | entityKind | stateType | 비고 |
|------|-----------|------------|-----------|------|
| **막부(군정)** | 가마쿠라 막부, 무로마치 막부, 에도 막부 | REGIME | SHOGUNATE | 쇼군이 실권을 가진 정권. 현대 국가 “일본”에 연결. |
| **시대(연호)** | 메이지 시대, 다이쇼 시대, 쇼와 시대 | PERIOD | HEREDITARY 또는 OTHER | 같은 나라의 기간 구분. “일본”에 연결. |

### 국가 형태(stateType) 권장

시스템의 **국가 형태**는 `HistoricalStateType`(stateType) 한 값이다.  
역사적 국가 폼·API에서는 **제국, 왕국, 공화국, 왕조**뿐 아니라 **막부(SHOGUNATE), 세습(HEREDITARY), 연방, 공국, 선제후국, … 기타(OTHER)** 등 전체 enum 값을 선택할 수 있다.

일본 사례별로 그중 어떤 값을 쓸지 권장은 아래와 같다.

| 일본 구분 | 국가 형태(stateType) | 폼에서 선택할 이름 | 이유 |
|-----------|----------------------|--------------------|------|
| **막부** (가마쿠라·무로마치·에도) | **SHOGUNATE** | **막부** | 쇼군 군정 전용 값. 목록에 “막부”로 있음. |
| **연호 시대** (메이지·다이쇼·쇼와 등) | **HEREDITARY** 또는 **OTHER** | **세습** 또는 **기타** | “제국/왕국”이 아닌 기간 구분. 천황제가 이어지는 기간이면 세습, 단순 기간이면 기타. |

- 막부는 반드시 **막부(SHOGUNATE)** 로 두면 필터·통계에서 “막부만” 조회하기 쉽다.
- 연호 시대는 “시대” 전용 값이 없으므로 **세습** 또는 **기타** 중 하나로 통일해서 쓰면 된다.

### 등록 순서 예시

1. **현대 국가**: 일본(Japan) 1건.
2. **역사적 정치체** (각 1건씩):
   - **가마쿠라 막부** — entityKind: 정권·군정, stateType: 막부, 연결: 일본
   - **무로마치 막부** — 동일
   - **에도 막부** — 동일
   - **메이지 시대** — entityKind: 시대, stateType: 세습 또는 기타, 연결: 일본
   - **다이쇼 시대**, **쇼와 시대** — 동일(시대)
3. **변천(Transition)**  
   - 무로마치 막부 → 에도 막부: **전환 성격 = 정권 교체**  
   - 에도 막부 → 메이지 시대: 정권 교체 또는 국가 계승(대폭번 후 신정부)에 따라 선택.

### 요약

- **막부** → `entityKind = REGIME`, `stateType = SHOGUNATE`, 현대 국가 “일본” 연결.
- **메이지/다이쇼/쇼와 등 연호 시대** → `entityKind = PERIOD`, `stateType = HEREDITARY` 또는 `OTHER`, “일본” 연결.
- 막부↔막부, 막부↔시대 변천은 **전환 성격**을 “정권 교체”로 두면, 국가 교체(신라→고려)와 구분해 조회·표시하기 좋다.
