# 행정부·각료·조직 수장 “한눈에 보기” 기능 설계

## 1. 요구 시나리오 정리

| 시나리오 | 예시 | 필요한 데이터 |
|----------|------|----------------|
| **A. 수반 재임 하의 각료** | 루즈벨트 대통령 시기 → 재무장관, 전쟁부장관 누구? | “이 수반 재임”에 묶인 각료 재임 목록 |
| **B. 수상 재임 하의 장관·총독** | 도조 히데키 수상 시기 → 대만총독, 외무대신 누구? | 위와 동일 + 조직(총독부) 수장과의 연결 |
| **C. 조직 역대 수장** | 대만총독부, 관동군, 만철 → 역대 수장 누구? | 조직별 “이 직위” 재임 목록 |

---

## 2. 현재 구조에서 가능한 것 / 부족한 것

### 2.1 이미 있는 것

- **GovernmentPositionTenure (재임)**
  - 인물 + 직위 유형(`HEAD_OF_STATE`, `HEAD_OF_GOVERNMENT`, `CABINET_MINISTER` 등) + 국가/역사국가 + 기간.
  - `positionDefinitionId` → **GovernmentPositionDefinition** 참조 가능.
- **GovernmentPositionDefinition (직위 정의)**
  - `organizationId` → **Organization** 연결됨.
  - 따라서 “대만총독”, “만철 총재”, “관동군 사령관” 같은 직위를 **조직별**로 정의해 두고, 재임에서 이 정의를 참조하면 **조직 역대 수장**은 이미 데이터 모델만으로 표현 가능.
- **Organization**
  - 만철, 관동군, 대만총독부 등 등록 가능. `GovernmentPositionDefinition.organizationId`로 직위와 연결됨.
- **AdministrationDepartment (행정 부처)**
  - 국가별 부처(국방부, 외교부, 재무부 등). 다만 “이 부처 장관 재임”과의 **직접 FK**는 없음. 직위 정의에는 `departmentName`(문자열)만 있음.

### 2.2 부족한 것

1. **“이 수반 재임 하에 있는 각료” 연결**
   - 현재는 재임끼리 부모-자식 관계가 없음.
   - “루즈벨트 재임” 한 건을 기준으로, 그 기간·국가에 맞는 “재무장관, 전쟁부장관” 재임을 **한눈에** 모아서 보려면 **상위 재임(parentTenureId)** 또는 이에 상응하는 연결이 필요함.
2. **행정 부처(AdministrationDepartment)와 “장관 재임”의 연결**
   - “미국 국방부 역대 장관”처럼 **부처 단위**로 재임을 묶으려면, 직위 정의 또는 재임이 해당 부처를 참조할 수 있어야 함.

## 3. 제안: 무엇을 바꾸고 추가할지

### 3.1 [필수] 수반–각료 연결: `parentTenureId` 추가

**대상:** `GovernmentPositionTenure` (재임)

**추가 필드:**

- `parentTenureId` (선택, FK → GovernmentPositionTenure.id)
  - 의미: “이 재임(각료/총독 등)은 저 재임(수반) 하에 있었다.”
  - 예: 루즈벨트 대통령 재임 ID를 부모로, “재무장관 홍길동” 재임에 설정.

**장점:**

- “루즈벨트 행정부” = 루즈벨트 재임 1건 선택 → `parentTenureId = 해당 id` 인 재임 목록 조회로 **각료·총독 등 한눈에 표시** 가능.
- 별도 “행정부(Cabinet)” 테이블 없이도 구현 가능.

**마이그레이션:**

- `government_position_tenure` 테이블에 `parent_tenure_id` 컬럼 추가 (nullable, FK, index).

---

### 3.2 [선택] 행정 부처와 직위 정의 연결: `administrationDepartmentId`

**대상:** `GovernmentPositionDefinition` (직위 정의)

**추가 필드:**

- `administrationDepartmentId` (선택, FK → AdministrationDepartment.id)
  - 의미: “이 직위는 이 행정 부처의 장관/차관 등이다.”

**효과:**

- “미국 국방부” 부처 상세에서 “역대 장관” = 이 부처를 참조하는 직위 정의들의 재임 목록으로 조회 가능.
- 국가·행정조직 화면과 “역대 수반/각료”를 같은 모델로 이어줌.

**마이그레이션:**

- `government_position_definition` 테이블에 `administration_department_id` 컬럼 추가 (nullable, FK, index).

---

### 3.3 조직 역대 수장 (만철, 관동군, 대만총독부 등)

**모델 변경 없음.**

- Organization 등록 후, 해당 조직용 **GovernmentPositionDefinition**을 만들고 `organizationId`를 붙임.
- 인물별 **GovernmentPositionTenure**에서 `positionDefinitionId`로 그 정의를 참조.
- **UI/API만 추가:**
  - 조직 상세 또는 “조직별 직위” 화면에서  
    `positionDefinition.organizationId = 조직 ID` 인 직위 정의들에 대한 재임 목록을 기간순으로 조회해 “역대 수장”으로 표시.

| 2 | **“행정부 한눈에 보기” 블록** | 예: “루즈벨트 행정부 (1933–1945)” 제목 아래에 수반 이름 + 기간, 그 다음 각료/총독 등을 직위별로 나열. |
| 3 | **조직 상세에 “역대 수장” 섹션** | 만철, 관동군, 대만총독부 등 조직 상세 페이지(또는 조직 선택 후 뷰)에 “역대 수장” 테이블/리스트 추가. `organizationId`로 직위 정의 → 재임 조회. |
| 4 | **재임 등록 시 “상위 재임” 선택** | 인물·재임 등록/수정 폼에서 “이 재임이 속한 수반 재임”(parentTenureId) 선택 가능하도록 필드 추가. |
| 5 | (선택) **행정조직(부처) 상세에 “역대 장관”** | AdministrationDepartment 상세에서 해당 부처를 참조하는 직위의 재임 목록 표시. |

## 5. 데이터 흐름 요약

- **연대표 / 국가 목록 / 국가 선택**  
  → 국가(또는 역사국가) 선택  
  → **역대 수반** (기존): `GovernmentPositionTenure` 중 수반 유형만 표시.  
  → **변경:** 수반 한 건 클릭 시 `parentTenureId = 해당 tenure` 인 재임 조회 → **행정부 각료/총독 등 한눈에 표시.**

- **인물**  
  → 기존처럼 재임 등록/수정.  
  → **추가:** “소속 행정부”(parentTenureId) 선택 가능.

- **행정조직**  
  → 기존: 국가별 부처 목록/계층.  
  → **추가(선택):** 부처별 “역대 장관” = 해당 부처를 참조하는 직위 정의의 재임 목록.

- **조직(만철, 관동군, 대만총독부 등)**  
  → **추가:** 조직 상세에 “역대 수장” = 해당 `organizationId`를 가진 직위 정의들의 재임 목록.

## 6. 정리

- **반드시 바꿔야 하는 것:**  
  **GovernmentPositionTenure**에 **parentTenureId** 하나 추가하면, “루즈벨트/도조 시기 그 행정부의 각료·총독·외무대신 등”을 한눈에 보는 기능을 구현할 수 있음.
- **이미 가능한 것:**  
  조직(만철, 관동군, 대만총독부) 역대 수장은 **현재 스키마만으로 가능**. 직위 정의에 `organizationId` 붙이고, UI/API에서 조직별 재임 목록만 조회·표시하면 됨.
- **선택 보강:**  
  행정 부처(AdministrationDepartment)와 “장관” 직위를 직접 엮고 싶다면, **GovernmentPositionDefinition**에 **administrationDepartmentId**를 추가하고, 부처 상세에 “역대 장관” API·화면을 붙이면 됨.

이 순서대로 적용하면 “수반 등록 → 그 행정부의 각료/총독 등록 → 한눈에 보기”와 “조직 역대 수장 한눈에 보기”를 깔끔하게 버무려서 구현할 수 있습니다.

## 7. 최적화·미래 지향 설계 (비교·부처 연동·과거 국가)

### 7.1 “다른 사람 등록 vs 내 등록” 비교

**요구:** 일본 행정부를 A가 등록한 내용과 B가 등록한 내용을 비교할 수 있어야 함.

**제안:**

| 구분 | 내용 |
|------|------|
| **추가** | `Cabinet`·`GovernmentPositionTenure`에 **등록자** 필드 추가. (다른 엔티티는 이미 `accountId` 사용: Country, HistoricalCountry, Person 등.) |
| **스키마** | `cabinet.account_id` (nullable, FK → Account), `government_position_tenure.account_id` (nullable, FK → Account). 등록/수정 시 로그인 계정으로 설정. |
| **API** | `GET /cabinets?countryId=&accountId=` 등으로 “내가 등록한 행정부” / “특정 사용자가 등록한 행정부” 필터. |
| **UI** | 행정부·각료 목록에 “등록자” 표시, 필터 “내 등록만 / 전체 / 사용자별”. “비교 보기” 시 두 계정(또는 내 vs 전체) 선택해 나란히 표시. |

→ **없애는 것 없음.** **추가:** `accountId` on Cabinet, GovernmentPositionTenure + API 필터 + 비교 UI.

---

### 7.2 직책(직위) 등록 방식: 지금이 최적인가?

**현재:** 직책 카테고리 등록 + 직책명 즉석 등록(기타) 혼용.

**정리:**

| 방식 | 용도 | 유지 여부 |
|------|------|-----------|
| **직위 정의(GovernmentPositionDefinition) 선택** | “재무장관”, “외무대신” 등 **정의된 직함**으로 등록. 부처(AdministrationDepartment)와 연결하면 “미국 국방부 역대 장관” 같은 조회 가능. | **유지·권장** (기본 흐름) |
| **기타 + 직책명 즉석 입력** | 정의에 없는 직함(예: “특별보좌관”)을 한 번만 쓰는 경우. | **유지** (보조 수단) |
| **직책 “카테고리”** | UI에서 쓰는 분류(국가원수, 정부수반, 각료 등)는 이미 **GovernmentPositionDefinition.positionType**(enum)으로 표현됨. 별도 “카테고리” 테이블을 또 두기보다는, 직위 정의 + positionType으로 통일하는 편이 최적. | **중복 제거 권장**: “직책 카테고리”를 별도 테이블로 두었다면, positionType/직위 정의로 흡수 검토. |

**최적화 방향:**

- **기본:** 직위 정의 목록에서 선택(국가/역사국가 필터 가능). 직위 정의에 **부처(administrationDepartmentId)** 를 연결하면, 행정조직(부처) 화면과 “역대 장관”이 자연스럽게 이어짐.
- **예외:** “기타” 선택 시 직책명·직책명(영문) 직접 입력은 그대로 두고, “가능하면 직위 정의를 먼저 만든 뒤 선택” 안내만 추가해도 충분.

→ **없애는 것:** 직위와 중복되는 “직책 카테고리”만 정리. **수정:** 직위 정의 ↔ 부처 연결 추가. **추가:** 부처 기준 역대 장관 API·UI.

---

### 7.3 행정부처(AdministrationDepartment) 테이블 — 필요 여부

**결론: 필요하다. 없애지 말 것.**

| 개념 | 역할 |
|------|------|
| **Cabinet (행정부)** | “한 수반(대통령·수상) 재임” 단위의 **내각** — 누가 언제 어떤 각료를 두었는지(시간·사람 중심). |
| **AdministrationDepartment (행정부처)** | 국가별 **부처/기관** — 국방부, 외교부, 재무부 등 **기관 자체**와 설립·폐지·후신(successor) 이력. |

- “도조 내각의 외무대신” → **Cabinet + Tenure** 로 표현.
- “일본 외무성(부처)의 역대 장관” → **AdministrationDepartment** + 그 부처를 참조하는 **직위 정의**의 재임 목록으로 표현.

**부족한 점:** 지금은 직위 정의에 `departmentName`(문자열)만 있고, **AdministrationDepartment와 FK로 연결되어 있지 않음.**

**추가 제안:**

- **GovernmentPositionDefinition**에 `administrationDepartmentId` (nullable, FK → AdministrationDepartment) 추가.
- “외무대신” 직위 정의 → “일본 외무성” 부처에 연결.
- 그러면 “행정부처 테이블”이 **부처별 역대 장관** 조회·표시의 기준이 되어, 행정부(내각) 뷰와 부처(기관) 뷰를 한 모델로 이을 수 있음.

→ **없애는 것 없음.** **추가:** 직위 정의의 `administrationDepartmentId` + 부처별 역대 장관 API·UI.

---

### 7.4 과거 국가(역사적 국가)의 각료 표현

**이미 가능:**

- `Cabinet`·`GovernmentPositionTenure` 모두 `historicalCountryId`를 갖고 있음.
- 역사적 국가(예: 일제 시대 일본, 조선)를 선택하면, 해당 `historicalCountryId`로 행정부·각료를 조회하면 됨.

**보강 제안:**

- API: `GET /cabinets?historicalCountryId=`, `GET /tenures?historicalCountryId=` 등 이미 countryId와 동일하게 historicalCountryId 필터 지원.
- UI: 국가 선택 시 “현대 국가 / 역사적 국가” 구분, 역사적 국가 선택 시 해당 국가의 행정부·각료만 표시. “과거 국가 각료”는 **추가 테이블 없이** 현재 스키마로 표현 가능.

→ **추가할 것:** 과거 국가용 필터·탭만 UI/API에서 명확히 해 주면 됨.

### 7.5 정리: 뭘 없애고 / 수정하고 / 추가해야 하는가

| 구분 | 대상 | 내용 |
|------|------|------|
| **없애기** | (선택) **직책 “카테고리”** | 직위 정의 + positionType과 역할이 겹치면, 카테고리 테이블/개념을 정리하고 직위 정의·enum으로 통일. |

| **수정** | **행정조직(부처) 화면** | 부처 상세에 “역대 장관” 블록 추가. 직위 정의의 administrationDepartmentId로 해당 부처 직위 재임 조회. |
| **추가** | **Cabinet** | `account_id` (nullable, FK → Account) — 등록자. |

**우선순위 제안:**

1. **단기:** Cabinet·Tenure에 `accountId` 추가 + API 필터 → “내가 등록한 것” vs “전체” 비교 가능.
2. **중기:** GovernmentPositionDefinition에 `administrationDepartmentId` 추가 + 부처 상세 “역대 장관” → 행정부처 테이블을 활용한 최적화.
3. **정리:** 직책 카테고리가 직위 정의와 완전 중복이면 점진적으로 직위 정의·positionType 쪽으로 통합.
