# 가문( Dynasty ) 국가 연동 검토

## 현재 구조

### 데이터 모델 (Prisma)
- **Dynasty**: 가문 자체. `name`, `description`, `startDate`, `endDate`, `thumbnailUrl`만 보유. **국가 FK 없음.**
- **DynastyRule**: 가문 ↔ **역사적 국가** 연결 (통치 기간 등).
- **DynastyModernRule**: 가문 ↔ **현대 국가** 연결 (통치 기간 등).
- **Person**: 선택적 `dynastyId`로 한 가문에 소속.

### API·UI
- 가문 CRUD: 국가 없이 **전역** 등록/수정/삭제.
- 연대표(국가) → 인물 → 가문 탭: **전체 가문 목록** 표시 (국가별 필터 없음).
- **DynastyRule / DynastyModernRule** 은 스키마만 있고 API·UI 미구현.

---

## 결론: “국가 없이 등록” 자체는 괜찮음

### 1. 도메인상 맞는 설계
- 한 가문이 **여러 국가**를 통치하는 경우가 있음 (예: 합스부르크 → 신성로마, 스페인, 오스트리아).
- 가문 엔티티에 `countryId`를 필수로 두면 “한 국가 소속”만 표현 가능해, 위 사례를 표현하기 어렵다.
- 따라서 **Dynasty는 국가에 종속되지 않고**, **Rule 테이블로 “어느 국가를 언제 통치했는지”** 표현하는 현재 스키마가 적절하다.

### 2. 인물–가문 연결
- 인물은 `dynastyId` 하나만 가지면 되고, 가문은 전역 풀에서 선택하면 된다.
- 인물 등록 시 “이 국가에 한정된 가문만 보여야 한다”는 필수 요구는 없으므로, **현재처럼 국가 없이 가문만 등록해 두고 인물에서 선택하는 방식**으로도 충분하다.

### 3. 단점·주의점
- **연대표에서 “한국” 선택 후 가문 탭**에 들어가면 **전체 가문**이 나와, “이 국가와 관련된 가문”만 보고 싶을 때 불편할 수 있다.
- **DynastyRule / DynastyModernRule** 이 API·UI에 없어, “조선 왕조 → 조선 (1392–1910)” 같은 **통치 기간·국가 연결** 정보는 아직 쌓이지 않는다.
- 그래서 “가문은 국가 없이 등록”만으로는 문제가 없지만, **국가별로 보기·통치 관계 관리**는 나중에 Rule을 노출하면 더 풍부해진다.

---

## 권장 방향

### 지금 단계 (유지)
- **가문은 계속 국가 없이 전역 등록**해도 된다.
- UI에 안내 문구만 추가해도 충분하다.  
  예: *“가문은 국가에 묶이지 않으며, 한 가문이 여러 국가와 연결될 수 있습니다.”*

### 이후 단계 (선택)
1. **국가별 가문 보기**  
   - 연대표에서 국가 선택 후 가문 탭일 때,  
     - **DynastyRule / DynastyModernRule** 이 있으면: “이 국가와 연결된 가문”만 필터해서 보여주기.  
     - “전체 가문 보기” 토글이 있으면 UX가 더 명확함.
2. **Rule API·UI**  
   - 가문 상세/수정 시 “통치한 국가 및 기간” (DynastyRule / DynastyModernRule) 등록·수정 기능을 넣으면,  
     - 국가별 필터와 “이 국가에서 이 가문이 통치한 기간” 표시가 가능해진다.

---

## 요약

| 항목 | 판단 |
|------|------|
| 가문을 국가 없이 등록하는 현재 방식 | **도메인·인물 연결 측면에서 문제 없음.** |
| DynastyRule / DynastyModernRule 미사용 | 스키마는 적절하나, API·UI가 없어 “통치 관계”는 아직 미활용. |
| 연대표 국가 페이지에서 전체 가문 노출 | 동작은 맞으나, 이후 “이 국가와 연결된 가문만 보기” 옵션 추가 권장. |

**정리:** 현재처럼 가문을 국가 설정 없이 등록하는 구조는 유지하고, 필요해지면 “국가별 필터”와 “통치 관계(Rule) 관리”를 단계적으로 추가하는 쪽이 무난하다.
