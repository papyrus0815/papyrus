# 사건 본문 문구·관직 설명 — 설계 옵션

사건 내용을 작성할 때 **문구**(용어, 고유명사)나 **관직**(대통령, 국왕 등)이 나오면, 독자가 이해할 수 있도록 **설명**을 붙이는 방법 정리.

---

## 현재 구조

- **본문**: `EventSection.content` (HTML). RichTextEditor에서 `@인물` 멘션은 `<span class="mention" data-entity-type="person" data-id="...">이름</span>` 형태로 저장됨.
- **관직 정의**: `GovernmentPositionDefinition`에 이미 **설명** 필드(`description`)가 있음. (관직 정의 관리 화면에서 “직위 설명” 입력 가능)
- **문구/용어**: 전용 엔티티는 없음.

---

## 방안 1: 관직만 본문에 연결 (기존 데이터 활용)

**목표**: 본문에 나오는 관직명(대통령, 국왕 등)을 “관직 정의”와 연결해, 보기 화면에서 설명을 툴팁/팝오버로 표시.

**방식**:
1. **에디터**: 인물 멘션과 비슷하게, 본문에서 **텍스트 선택 후 “관직 연결”** 메뉴 → 관직 정의 목록에서 선택 → 해당 텍스트를  
   `<span class="position-term" data-position-definition-id="...">대통령</span>` 형태로 감싸서 저장.
2. **API**: 기존 관직 정의 목록/단건 조회 API 사용. (이미 있음)
3. **상세 보기**: `.position-term`에 마우스오버 또는 클릭 시 `data-position-definition-id`로 관직 정의 조회 후 `description`을 툴팁/팝오버로 표시.

**장점**: DB/API 변경 없이 프론트만 확장 가능.  
**단점**: “문구”(삼권분립, 선거인단 등)는 다루지 못함.

---

## 방안 2: 문구·용어까지 — 용어(Glossary) 엔티티 신규

**목표**: 문구·고유명사에도 설명을 붙이고, 본문에서 클릭/호버 시 설명 표시.

**방식**:
1. **엔티티**: `GlossaryTerm` (또는 `Term`) 테이블 신규  
   - `id`, `name`(표시명), `description`(설명), (선택) `countryId` / `historicalCountryId` 등.
2. **에디터**: 텍스트 선택 → “용어 연결” →  
   - 기존 용어 검색 후 선택, 또는  
   - “새 용어 등록”(이름 + 설명) 후 선택  
   → `<span class="term" data-term-id="...">문구</span>` 저장.
3. **상세 보기**: `.term` 클릭/호버 시 해당 용어의 `description` 표시 (인물 멘션 모달과 유사한 UX 가능).

**관직과의 관계**:
- **A안**: 관직은 “관직 연결”(방안 1)만 쓰고, 문구만 용어로 관리.
- **B안**: 관직도 용어로 통일 — 관직 정의의 `title`+`description`을 용어로 노출하거나, “관직 연결” 시 내부적으로 해당 관직 정의를 참조하는 용어로 저장. (구현 복잡도는 더 높음)

**장점**: 문구·관직 모두 한 가지 패턴(선택 → 설명 표시)으로 확장 가능.  
**단점**: API·DB·관리 화면(용어 CRUD) 추가 필요.

---

## 방안 3: 사건 폼에 “관련 용어/관직 설명”만 추가 (본문 연동 없음)

**목표**: 본문 에디터는 건드리지 않고, “이 사건에서 중요한 문구·관직”과 그 설명만 입력.

**방식**:
1. **사건 폼**에 “관련 용어·관직 설명” 블록 추가  
   - 예: (용어/관직명, 설명) 쌍을 여러 개 입력하거나,  
   - 한 줄 요약 형태의 자유 텍스트.
2. **저장**: Event에 `relatedTermsDescription`(Text) 같은 필드 추가하거나, JSON/별도 테이블로 (이름, 설명) 리스트 저장.
3. **상세 보기**: “이 사건에서 쓰인 용어·관직” 섹션으로 위 내용만 표시. 본문의 특정 단어와 자동 링크는 없음.

**장점**: 구현이 가장 단순하고, 본문 HTML/에디터 로직 변경 없음.  
**단점**: 본문에서 해당 단어를 클릭해 설명을 보는 UX는 불가.

---

## 추천 조합

| 우선순위 | 내용 |
|----------|------|
| **1단계** | **방안 1** — 관직 정의 설명을 본문과 연결. (에디터에 “관직 연결”, 상세에 툴팁/팝오버) |
| **2단계** | **방안 2** — 용어(Glossary) 엔티티 + “용어 연결” + 상세에서 설명 표시. 문구까지 확장. |
| **빠른 적용** | **방안 3** — 당장은 “관련 용어·관직 설명” 필드만 추가해 상세에 블록으로 노출. |

방안 1은 기존 관직 정의의 “직위 설명”을 그대로 활용하므로, **문구/관직 중 관직 설명이 더 시급하다면** 1단계만 먼저 적용하는 것도 가능합니다.

---

## 구현 현황 (방안 2 적용)

- **DB**: `GlossaryTerm` 모델 추가 (name, description, countryId, historicalCountryId). 마이그레이션: `npx prisma migrate dev --name add_glossary_term` (datasource URL 설정 필요).
- **API**: `GET/POST /glossary/terms`, `GET/PUT/DELETE /glossary/terms/:id` (인증 필요). 쿼리: countryId, historicalCountryId, q(검색).
- **에디터**: 본문에서 텍스트 선택 후 우클릭 → "용어 연결" → 기존 용어 검색 선택 또는 "새 용어로 등록 후 연결". 저장 시 `<span class="term" data-term-id="..." data-term-name="...">텍스트</span>`.
- **상세 보기**: 본문 내 `.term` 클릭 시 설명 팝오버 표시 (용어 API 단건 조회). 바깥 클릭 또는 Escape로 닫기.
