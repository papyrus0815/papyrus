# 방향 A — 「레저 그리드 (Ledger Grid)」

> **설계 명제**
> 행을 flex 밀착에서 **6트랙 CSS grid**로 바꿔 모든 슬롯에 세로 스캔선을 세우고,
> 들여쓰기는 행이 아니라 **제목 셀 안의 서브그리드**가 소유하며,
> 폭 상한은 행(880px)에서 **컨테이너(1144px)** 로 올려 남는 가로는 상세 패널이 상시 점유한다.
>
> 한 줄 요약: **원장(ledger)은 열이 먼저 있고 값이 나중에 온다.** 지금은 값이 먼저 있고 열이 없다.

---

## 0. 왜 격자인가 — 진단이 말하는 근인

진단 ALIGN 렌즈의 명제가 그대로 근인이다: *"이 목록에는 열이 존재하지 않는다 — 행마다 자기만의 flex 컨테이너가 있다."*
실측이 그것을 증명한다.

| 슬롯 | 오늘의 x 고유값 | 원인 |
|---|---|---|
| 제목 좌측 | **11종** (219~265, 46px 스프레드) | 앞에 놓인 카테고리 칩이 34/43/52/56px 가변 |
| 기간 | **157종** (299~840) | 제목 뒤 밀착 → 제목 폭 9배 분산(72~648)이 그대로 전이 |
| 국기 | **161종** (323~899) | 위와 같음 + 묶음 폭 36~283px |
| 액션 | **3종** | `margin-left:auto`로 한 번 고쳤으나 depth 들여쓰기가 22px 되밀어냄 |
| 콘텐츠 우측 끝 | **4개** (985 / 1403 / 1407 / 1419) | Body 880 캡 vs hairline vs 세기 카운트 |

즉 오늘의 목록은 **252개의 서로 다른 레이아웃**이다. 우연히 겹치는 구간이 있을 뿐이다.
격자는 이 252개를 **1개의 레이아웃 + 252개의 값**으로 바꾼다.

그리고 두 번째 근인: `Body{max-width:880px}`. 이 상한은
- 지키는 게 없고(252행의 콘텐츠 자연 최대 폭 870px, 실제 잘림 1행),
- 만드는 건 행 **안**의 빈칸뿐이며(1440에서 412px, 1920에서 892px),
- **메타를 고정 열로 되돌릴 여지를 원천 봉쇄**한다.

880을 걷어내지 않으면 격자를 만들 수 없다. 그래서 SPACE-1은 이 방향의 **선결 조건**이다.

## 1. 레이아웃 — 6트랙 원장 격자

### 1.1 트랙 정의 (wide 밴드 기준)

`Body`를 flex → grid로 바꾸고, 트랙 폭은 **CSS 변수 6개**로 선언한다.
밴드(반응형)는 이 변수 6개만 다시 선언한다 — `grid-template-columns` 자체는 한 곳에만 존재한다.

```css
/* CompactList (또는 CatalogSection)에서 선언 — 행·세기헤더·연도헤더·스켈레톤이 공유 */
--col-date:  60px;
--col-cat:   60px;
--col-dur:   56px;
--col-flags: 128px;
--col-act:   60px;
--col-gap:   12px;
--row-indent: 24px;   /* depth 1단 */

/* Body / CenturyDivider / YearDivider / CollapsedPlaceholder / SkeletonBody 공통 */
display: grid;
grid-template-columns:
  [date]  var(--col-date)
  [cat]   var(--col-cat)
  [title] minmax(0, 1fr)
  [dur]   var(--col-dur)
  [flags] var(--col-flags)
  [act]   var(--col-act);
column-gap: var(--col-gap);
align-items: baseline;          /* ALIGN-11 */
```

> ⚠️ **subgrid를 쓰지 말 것.** `RowList`가 연도 그룹마다 별도 DOM이라(event-compact-list.tsx:528) subgrid·`auto`·`max-content` 트랙은 그룹마다 다른 폭을 만들어 세기 경계에서 열이 어긋난다.
> **고정 px 트랙 5개 + `minmax(0,1fr)` 1개**만이 전 그룹 공통 축을 만든다 — 모든 행 박스의 폭이 동일하므로 `1fr`의 계산값도 전 행 동일하다. 이것이 subgrid 없이 열을 세우는 유일한 정공법이다.

### 1.2 폭 산정 근거 (전부 실측에서 역산)

| 트랙 | 폭 | 정렬 | 근거 |
|---|---|---|---|
| `date` | **60px** | **right** | 값 3종의 최대 폭: `7.27`≈24px · `(1893)`≈40px · `BC 1046`≈44px · `1893.4.12`≈56px(1행 버킷 승격 대비). 우측 정렬이면 `7.27`·`12.31`·`(1893)`의 끝자리가 한 축에 선다(ALIGN-5). 현행 `min-width:36px` 좌측 정렬은 값 길이에 따라 2px 흔들리고 49행(19%)이 슬롯을 넘었다 |
| `cat` | **60px** | 칩이 셀 100% | 칩 실측 4종 34/43/52/56 → 최장 `전쟁/군사`(라벨 46px + padding 12 = 58) 수용. 칩을 `width:100%`로 채우고 라벨 가운데 정렬 → **칩의 좌·우 두 모서리가 모두 단일 스캔선**이 된다(현행은 좌측선조차 없음) |
| `title` | **minmax(0, 1fr)** | left | 상한을 트랙이 아니라 **컨테이너**가 정한다(§1.4). 그래서 `minmax(280,616)` 같은 이중 상한이 필요 없다 |
| `dur` | **56px** | **right** | 기간 최대 실측 58px(`11개월 30일`)이나 이 값은 1행뿐 → 56에서 말줄임 대신 tabular 축소. 우측 정렬 → **'오래 지속된 사건 찾기'가 세로 스캔으로 성립**(ALIGN-4의 과업) |
| `flags` | **128px** | left | 국기 묶음 p50 36 / p90 133. 128 = p90 수용 + `+N` 칩(26px)은 클리핑 박스 **밖** 형제로 배치(ADAPT-2) |
| `act` | **60px** | **right** | 28(요약) + 4 + 28(북마크) = 60. 북마크가 항상 마지막 → 그 우측 모서리가 행의 단일 우측 기준선 |
| `column-gap` | **12px** | — | 8px 그리드 정합(8×1.5). 현행 gap 8은 칩·제목이 붙어 읽혀 열 인상이 안 난다. 5개 gap = 60px |

**고정 합계** = 60+60+56+128+60 = 364 + gap 60 = **424px**.
`title` 트랙 = `Body 폭 − 424`.

### 1.3 최대 난제 — depth 들여쓰기 22px를 격자 안에서 처리하기

세 가지 안을 전부 검토했다.

| 안 | 동작 | 판정 |
|---|---|---|
| (a) 행 전체를 민다 (현행) | `Stop{margin-left: depth*22}` | **기각.** 액션 우측 끝이 985(depth0) / 1007(depth1)로 갈리고 날짜·칩 x도 22px 이동한다(ALIGN-3). 계층과 무관한 축까지 들여쓰기가 번진다 |
| (b) 열 자체를 민다 | `grid-template-columns`의 첫 트랙을 `calc(depth*24px)`로 | **기각.** 트랙 정의가 행마다 달라지면 격자가 아니다 — date·cat도 함께 이동해 ALIGN-5가 무효화된다 |
| (c) **들여쓰기를 제목 셀 안으로** | 제목 셀이 자체 서브그리드를 갖는다 | **채택** |

**채택안 (c) — 제목 셀 = 3열 서브그리드**

```css
/* title 셀 */
display: grid;
grid-template-columns:
  [ind]  min(calc(var(--depth) * var(--row-indent)), 96px)   /* depth 4단에서 클램프 */
  [disc] 28px                                                 /* 디스클로저 컨트롤 */
  [text] minmax(0, 1fr);
column-gap: 0;
align-items: baseline;
```

- **셰브론이 tree 열이 아니라 제목 셀 안으로 들어온다.** 그 결과 행의 **첫 열은 날짜**가 된다 — 연대기 목록의 정렬 키가 행의 맨 앞이라는 것은 그 자체로 옳은 진술이다.
- depth 신호는 `[ind]` 트랙 하나가 전담한다. 날짜·칩·기간·국기·액션은 depth와 **완전히 무관**해진다 → 액션 x 3종 → **1종**, 날짜 x → **1종**.
- 제목 텍스트 x는 depth 0/1/2에서 **정확히 24px씩** 계단진다(현행 11종·46px 무작위 스프레드 → **2종·24px 규칙적 계단**). 계단이 사라지는 게 아니라 **의미 있는 계단만 남는다**.
- `--row-indent: 24px` (현행 22px). 22는 gap 8·셰브론 20·날짜 36·액션 28 어느 값의 배수도 아니었다(ALIGN-13). 24 = 8×3이고 WCAG 2.2 SC 2.5.8의 24×24 타깃과도 정합한다.
- depth ≥ 5는 `min(..., 96px)`로 클램프하고 제목 앞에 `⋯4` 마이크로 라벨을 붙인다(`event_parent_link` 다중 상위 도입 대비).
- `--depth`는 styled-components의 동적 prop이 아니라 **인라인 CSS 변수**로 넣는다: `style={{ ['--depth' as string]: depth }}`. prop으로 넣으면 depth마다 클래스가 생성돼 252행에서 클래스 캐시가 부풀고 memo 이득이 깎인다.

**디스클로저 컨트롤 병합 (ALIGN-12 일부)**
`[disc]` 28px 안에 셰브론(11px 글리프) + 자식 수를 **한 컨트롤**로 합친다: `▸3`.
- 자식 없는 행도 28px를 예약한다(현행 ExpandSpacer 20 + gap 8 = 28과 동일 예산, 순증 0).
- `aria-label`은 현행 문구 유지(`하위 사건 N개 펼치기/접기`), 배지의 `aria-hidden` 정책도 유지 → **회귀 금지 2항 무영향**.
- 히트 영역 `::before{inset:-6px -4px}` 유지 → 40×32.

### 1.4 폭 상한을 행에서 컨테이너로 (SPACE-1 · ALIGN-2)

```css
/* event-list-item.tsx */
- const Body = styled.div`  max-width: 880px;  `      /* 삭제 */

/* list.styles.ts */
export const CatalogSection = styled.section`
  width: min(100%, 1144px);
  margin-right: auto;
`
```

**1144의 산출**
`Body 1032`(= title 608 + 고정 424) + `Stop padding 28`(14+14) + `우측 패딩 12` + `좌측 거터 70` + `카드 보더 2` = **1144px**.
title 608 → 텍스트 폭 580(disc 28 제외) → **잘림 1행**(ALIGN-9 곡선: 560→1, 616→1). 오늘과 동일하다.

**우측 기준선 4개 → 1개**
- `Stop`: `margin-right: 0` (현행 유지, hairline은 Stop border-box 폭)
- `CenturyDivider` / `YearDivider`: `margin-right: 0` (현행 `-12px` 제거)
- 세기·연도 카운트: **`act` 열에 배치**(§4) → 북마크 우측 모서리와 같은 x

→ 행 hairline·그룹 hairline·세기 카운트·액션 우측 끝이 **모두 카드 콘텐츠 우측 끝** 하나로 수렴한다.

### 1.5 행 높이·패딩

| 항목 | 값 | 비고 |
|---|---|---|
| 행 높이 | **45px 유지** | 8(pad) + 28(액션 버튼) + 8(pad) + 1(border). 제목을 14→15px로 올려도 라인박스 19.5px < 28px라 **0px 증가** |
| `Stop` padding | `8px 14px` | 현행 `8px 12px 8px 14px` → 좌우 대칭. 좌측 14는 유지(hairline·tint 블리드 좌표 불변) |
| 정렬 | `align-items: baseline` | 단, `disc`·`flags`·`act` 셀만 `align-self: center` |
| 베이스라인 보정 | 칩 `line-height:18px; height:18px; padding:0 6px` / 기간 `line-height:18px` | 현행 칩 line-height 1.5(15.75px 라인박스)가 제목(18.2px)과 어긋나 전 행 1.51px 드리프트를 만들었다(ALIGN-11) |
| `font-variant-numeric` | `Stop`에서 **제거**, `date`·`dur`·`disc 카운트`·헤더 카운트에만 국소 선언 | 등폭 숫자는 숫자가 세로로 쌓일 때만 값을 한다. 제목 109/252행(43%)이 숫자를 포함하는데 전역 tabular가 그 제목만 최대 7px 넓혀 잘림 임계를 앞당기고 있었다(ALIGN-10). 제거하면 잘림 임계가 ~6px 뒤로 밀린다 |

## 2. 타입·색 토큰 — 슬롯당 하나씩

### 2.1 크기 3단 (TYPE-10)

행 안 5단(10 / 10.5 / 11 / 12 / 14) → **3단(15 / 12 / 10.5)**. 인접 단차 0.5px는 위계를 0비트 실어 나른다.
`theme.ts`에 소비처 단일 출처를 추가하고 목록은 리터럴을 쓰지 않는다:

```ts
export const ROW_TYPE = {
  title: '15px',   // 주역
  meta:  '12px',   // 날짜·기간·근거·힌트
  chip:  '10.5px', // 카테고리 칩·국가 칩·자식수
} as const
```
트래킹도 5종 → **2종**: 제목 `-0.005em`, 나머지 전부 `0`.
`font-size` 미선언 버튼(현재 13.333px 유령으로 렌더되는 ExpandBtn 4개)에 명시.

### 2.2 슬롯별 토큰 (라이트 / 다크)

| 슬롯 | size | weight | 라이트 | 다크 | 대비(라/다) |
|---|---|---|---|---|---|
| 제목 | 15 | 700 | `#0f172a` | `#f1f5f9` | 17.9 / 16.8 |
| 제목(문맥강등) | 15 | **500** | `#6b7280` | `#a1a1aa` | 4.83 / 7.19 |
| **날짜(datum)** | 12 | **600** | `#4b5563` | `#d4d4d8` | **7.56 / 12.46** |
| 기간(measure) | 12 | 500 | `#6b7280` | `#a1a1aa` | 4.83 / 7.19 |
| 매칭 근거 | 12 | 500 | `#6b7280` | `#a1a1aa` | 4.83 / 7.19 |
| 근거 kind 칩 | 10.5 | 600 | `#854d0e` on `rgba(251,191,36,.22)` | `#fcd34d` on `rgba(251,191,36,.16)` | AA |
| **'조건 밖 N'(action)** | 12 | **600** | `#2563eb` + 1px 점선 밑줄 | `#93c5fd` | 5.17 / 8.9 |

**핵심 역전 수정 (TYPE-1)**: 오늘 행에서 가장 강한 텍스트는 날짜가 아니라 분류 칩이다(라이트 칩 5.37~8.70:1 / 날짜 4.83:1, 칩 600 vs 날짜 500). 연대기 목록의 **정렬 축이 가장 약한 토큰**이라는 뜻이다.
→ 날짜를 12/600 `#4b5563`(7.56:1)으로, 칩 굵기를 600→500으로 내린다. 칩의 hue 대비는 유지하되 **굵기 축에서 날짜에 양보**한다.
결과 사다리: **15/700 → 12/600 → 10.5/500** 이 크기·굵기 양축에서 단조.

**metaText 4역할 → 3층 분화 (TYPE-8)**
① datum(날짜) 12/600 `#4b5563` ② measure(기간·근거) 12/500 metaText ③ action('조건 밖 N') 12/600 브랜드 블루 + 점선 밑줄, hover 실선.
`FilteredOutHint`는 이 목록의 **유일한 인터랙티브 텍스트**인데 지금은 39×13px에 어포던스 0이다. 히트 확장 `::before{inset:-6px -4px}` → 47×25(ADAPT-7).

### 2.3 색 예산 — 카테고리 3중 인코딩 해체 (TYPE-3 → TYPE-2 자동 해소)

오늘 카테고리는 **도트 hue + 칩 배경 tint + 칩 라벨 hue + 한글 라벨** = 한 속성에 4채널. 정보량은 2.71비트(상위 5종이 90%)뿐이다.
격자가 카테고리에 **고정 60px 열**을 주는 순간 도트의 hue는 순수 중복이 된다.

- 레일 행 도트: hue 제거 → 중립 단색. 라이트 `#64748b`(4.8:1) / 다크 `#71717a`(3.96:1) — 다크에서 최빈 3색이 1.78~2.85:1로 배경에 잠기던 문제(TYPE-2, 행의 64%)가 함께 사라진다.
- 활성 행 도트만 `BRAND.primary` **8px**. 레일 위계를 세기 12 > 연도 10 > 행 6 / 활성 8로 재배분(RHYTHM-6) — 지금은 활성 행 도트 11px가 자기 연도 헤더 도트 10px보다 크다.
- 카테고리 hue는 **칩이 단독으로** 싣는다 → 목록↔타임라인↔격자 색 통일 canon 유지.
- 행당 유채색 마크 5 → **1(+국기)**.

**amber 4중 과부하 (TYPE-6 vs RHYTHM-13 충돌 — 결정 필요했던 지점)**
진단은 서로 반대되는 두 처방을 냈다: TYPE-6 = amber를 북마크 전용, RHYTHM-13 = amber를 검색 전용.
**채택: 검색 전용.** 이유 — 검색 하이라이트(`<mark>`)는 웹 관습상 amber가 강하게 코딩돼 있고 제목 텍스트 *안*에 나타나므로 대체 채널이 없다. 북마크는 **형태 채널(fill 유무)** 이 이미 있다.
- `Mark`: 라이트 `bg #fde68a / color #0f172a`(14.33:1), 다크 `bg #fbbf24 / color #1c1917`(10.48:1) — **color를 강제**한다(현행 `color:inherit`이라 다크 매칭 근거가 1.99:1까지 떨어졌다, TYPE-5).
- `MatchReasonKind`: amber 유지.
- 북마크: ON = **채워진 글리프 + `text.primary`**(라이트 17.9 / 다크 16.8), OFF = 아웃라인 + 55% alpha(4.0/4.4). 현행 ON `#f59e0b`는 라이트 2.15:1로 **OFF(4.00:1)보다 덜 보였다**(TYPE-7).
- 종교 카테고리 칩과 kind 칩의 hex 충돌(`#854d0e`/`#fcd34d` 동일)은 남지만, kind 칩은 검색 중에만 나타나고 칩은 `cat` 열에 고정되어 **위치로 구별**된다.

### 2.4 이모지 국기 (TYPE-12)

디자인 시스템이 제어할 수 없는 두 번째 색 체계다. 목록 밀도에 한해:
`filter: saturate(0.8)` + 12→11px, 행 hover/active에서만 `saturate(1)`. 정보는 유지, 정지 상태 채도만 회수.
`NameText` 10px → 10.5px(칩 스케일 합류, 10px 단 제거).

## 4. 그룹 헤더 — 헤더도 같은 격자를 쓴다

이것이 이 방향의 두 번째 핵심 주장이다. **세기·연도 헤더가 행과 다른 레이아웃을 쓰는 한 우측 기준선은 절대 하나가 되지 않는다.**

```css
/* CenturyDivider / YearDivider — Body와 동일 6트랙 */
display: grid;
grid-template-columns: /* 동일 */;
column-gap: var(--col-gap);
padding-left: calc(var(--rail-inset) + 14px);   /* 라벨이 date 열 좌측에 정확히 착지 */
margin-right: 0;                                 /* 우측 기준선 통일 */
```

| 셀 | 세기 헤더 | 연도 헤더 |
|---|---|---|
| `date`~`title` (span 3) | `21세기` 20px/800 + `(2001–2100)` 12/500 metaText | `2026년` 14px/700 |
| `dur`, `flags` | 비움 | 비움 |
| `act` | `30건` 12/600 metaText, **우측 정렬** | `6건` 12/600 metaText, **우측 정렬** |

**해소되는 것**
- ALIGN-14: 같은 데이텀(건수)에 반대 정렬을 쓰던 문제(세기=우측 1403 / 연도=라벨 옆 159) → 둘 다 `act` 열.
- RHYTHM-8: 표기 3종('30건' / 단위 없는 '6' / '6행이 접혀있습니다') → **`N건` 통일**, 자식이 있어 M≠N이면 `N건 · M행`.
- TYPE-4: `YearDivider span { font-size:14px; font-weight:700 }`(specificity 0,1,1)가 `CollapsedCount`(0,1,0)를 이겨 카운트가 14/700 primary로 렌더되던 버그 — **'2026년 6'이 '2026년 6월'로 읽힌다**. 카운트를 별도 그리드 셀로 분리하면 부모 선택자 상속 경로가 끊겨 근본 해소된다. 덤으로 단위 '건'이 붙어 오독이 불가능해진다.
- RHYTHM-7(부분): 세기 20/800 vs 연도 14/700 = 1.43× 로 층간 대비를 벌린다.

**높이**: 세기 `min-height: var(--century-header-h)` 44px 유지(회귀 금지 4항 — YearDivider가 `top`으로 이 값에 붙는다).
연도 헤더 블록 63px → **44px**(margin 22/8 → 10/4, padding 8/8 → 5/5, 라벨 라인 20px). 88개 × 19px = **1,672px 회수**.

**접힘 표현**
`CollapsedPlaceholder`도 같은 격자. `title` 셀에 `N건 · M행 접힘`, `act` 셀 비움. 높이 29 → **20px**(margin 1/4→0/2, padding 4/4→2/4).
sticky 규약은 손대지 않는다 — **CenturySection/YearSection 래퍼와 시각적 숨김 GroupHeading은 그대로**(회귀 금지 1·2항).

## 5. 반응형 — 밴드 사다리

### 5.1 측정 축을 뷰포트에서 컨테이너로 (ADAPT-3)

`@media (max-width: 640px)` 단일 임계로는 상세 패널이 행 폭을 460px 깎는 것을 **볼 수 없다**.
→ `CatalogSection`에 `container-type: inline-size; container-name: catalog;`, 밴드는 `@container catalog (...)`.

> ⚠️ **container-type은 스크롤 컨테이너(CompactList)가 아니라 카드(CatalogSection)에 건다.** `container-type: inline-size`는 `contain: layout inline-size style`을 함의하고, 이를 스크롤포트에 걸면 내부 sticky 헤더 동작이 브라우저별로 흔들릴 수 있다. 카드에 걸면 sticky의 containing block(YearSection/CenturySection)과 스크롤포트(CompactList)가 모두 containment **안쪽**에 남아 영향이 없다. 이것이 배치 1의 1순위 검증 항목이다.

JS 쪽 `isNarrow`(boolean)는 **`density: 'wide'|'mid'|'narrow'|'mobile'` 4값**으로 승격한다(칩 개수는 CSS로 못 정한다). 계산은 `CatalogSection`에 `ResizeObserver` **1개** — 행별 리스너 금지 규약 유지.

### 5.4 모바일(≤600 컨테이너) — 2행 격자

flex-wrap + `order` + 0높이 스페이서(RowBreak) 대신 **명시적 2행 격자**로 바꾼다. 회귀 금지 5항이 지키려던 것(제목 `flex:1 1 0`의 basis 0, Flags 112px, max=1)은 격자에서 구조적으로 보장된다 — 그리드 트랙은 `flex-basis: auto` 함정이 없다.

```css
@container catalog (max-width: 600px) {
  grid-template-columns: 28px minmax(0,1fr) auto auto 28px;
  grid-template-rows: auto auto;
  row-gap: 3px; column-gap: 8px;
  /* 1행: 제목이 2~5열 span, disc는 1열 */
  /* 2행: date(1열 시작) cat dur flags act */
}
```
- **좌측선 1개**: 현행 390px에서 제목 x=83 / 날짜 x=55 / 칩 x=93의 **3개 좌측선**(ALIGN-7·ADAPT-5)이 격자에서 소멸한다. disc를 1열에 두고 제목을 2열에서 시작시키면 두 줄이 모두 같은 x에서 시작한다.
- **기간 부활**(ADAPT-8): `display:none` 삭제. 억제 축을 뷰포트 → **콘텐츠**로 바꿨으므로('1일'은 `·` 1글자, §6) 모바일에서도 105행의 정보성 기간이 살아난다. 현행은 정확히 반대로 걸려 있다 — 데스크톱에 잉여 133개를 그리고 모바일에서 정보성 105개를 지운다.
- **매칭 근거**(ADAPT-9): `display:none` 삭제. 검색 활성 시에만 3행차로 강등(`-webkit-line-clamp:1`), 행 높이 71→92px는 **검색 중에만**. 현행은 모바일 검색 결과의 76%가 무근거다.
- **국기**: `max-width: min(112px, 30cqw)` → 320px에서 68px. 현행 고정 112px는 320px에서 94행(37%)을 3줄(93px)로 무너뜨린다(ADAPT-6).
- **들여쓰기**: `--row-indent: 12px` (1440의 24px는 Body의 2.6%지만 390px에서는 7.5% → 3배 대가, ADAPT-10).

### 5.5 국기 열 — 개수가 아니라 **폭 예산**으로 자른다 (ADAPT-2 · ALIGN-4)

현행 `max={isNarrow ? 1 : 3}`은 상수다. 그런데 역사국가는 이모지가 없어 국가명 전체가 텍스트 칩이라 3개면 270px에 달한다 → 128px 셀에서 글리프 중간이 잘려 **'이탈'·'그레이트' 같은 존재하지 않는 국가명**이 만들어진다(641px에서 8개국 행이 132px 잘리고 '+5'까지 소멸).

## 6. 기간 토큰 — '1일' 133행을 어떻게 처리하는가 (TYPE-13)

252행 중 기간 토큰 238개, 그중 **'1일' 133개(56%)**. 유일한 정량 데이텀의 절반 이상이 자명한 값이다.

진단의 두 처방(① 완전 생략 ② opacity 0.55 강등)을 둘 다 검토했고 **둘 다 부족**하다고 판단했다.
`formatDuration`은 이미 `!end → ''`(종료 미상)와 `same-day → '1일'`(당일 종료 확정)을 **다른 사실로 구별**하고 있다(event-list-item.tsx:152-162 주석이 명시). 완전 생략하면 이 구별이 133행에서 소멸한다 — 정보 손실이 0이 아니다.

**채택: 3상태 열**

| 상태 | 렌더 | 폭 |
|---|---|---|
| 종료 미상 | 빈 셀 | 0 |
| 당일 종료 확정 | `·` (11px, metaText, opacity .5) + `<VisuallyHidden>1일</VisuallyHidden>` | ~6px |
| 지속 사건 | `11일` · `1개월 19일` · `15년 9개월` (12/500, 우측 정렬, tabular) | ~24~56px |

- **`formatDuration`은 손대지 않는다.** 반환 문자열 `'1일'`을 행이 렌더 시점에 분기한다 → precision 가드(회귀 금지 9항)에 코드 한 줄도 닿지 않는다.
- 결과: 우측 정렬 열에 **105개의 의미 있는 값만 텍스트로** 남고, 133개는 6px 점으로 눌린다. 세로로 훑으면 '지속된 사건'이 즉시 골라진다 — ALIGN-4가 말한 과업이 처음으로 성립한다.
- 접근성: 점은 `aria-hidden`, 시각적 숨김 텍스트가 '1일'을 낭독 → 스크린리더 정보량 불변.

## 7. 로딩 스켈레톤 · 빈 상태

### 7.1 스켈레톤 — 격자와 리듬을 모두 예고 (RHYTHM-14 · ADAPT-13)

현행 스켈레톤은 45px 행 12줄만 그린다. 실제 도착 화면은 크롬이 35%(세기 헤더 44 + 연 헤더 44 + 행…)라 **로딩 화면이 최종 리듬을 거짓말한다**.

```
[세기 헤더 placeholder ×1]   44px — 라벨 바 90×16, act 열에 카운트 바 28×12
[연 헤더 placeholder  ×1]    44px — 라벨 바 60×14
[행 ×4]                      45px
[연 헤더 placeholder  ×1]    44px
```

## 9. 잃는 것 — 정직한 계산

이 방향은 공짜가 아니다. 세 가지를 잃는다.

### 9.1 제목 뒤 메타 밀착으로 얻었던 밀도

2026-07-22 결정('좌측 밀착으로 죽은 여백 제거')은 **880px 창 안에서만 참**이었지만, 그 안에서는 진짜 이득을 냈다. 격자는 그것을 버린다.

| 제목 폭 | 오늘 제목→기간 거리 | 격자(1440, title text 469) | 배수 |
|---|---|---|---|
| min 72 | 8px | **397px** | 50× |
| p50 177 | 8px | **292px** | 37× |
| p90 331 | 8px(최대 50) | **138px** | 17× |
| max 613 | 8px | 0(말줄임) | — |

**즉 격자는 빈 픽셀을 줄이지 않는다. 위치만 바꾼다** — 행 우측 끝의 412px 한 덩어리에서, 제목과 기간 사이의 p50 292px으로.
방어 논리: 같은 빈 픽셀이라도 ⑴ 열린 모서리에 있으면 '깨진 행'이고 ⑵ 두 스캔선 사이에 있으면 '칸'이다. 그리고 292px 건너편에 **무엇이 있는지 학습 가능**해진다(오늘은 매 행 다른 곳에 있다).
완화: hover 리더 점선(§8), 행 전체 hover tint.
**이 항목은 완전히 해소되지 않는다.** 짧은 제목 행에서 제목↔국기 시선 이동은 실제로 길어진다.

### 9.2 말줄임 1행 → N행

| 뷰포트 | 오늘(비선택) | 오늘(선택) | 격자 |

| 1600 | 1행 | ~3행 | **1행** |

| 834 | 30행(실측) | — | ≈31행 |

641~1023 대역은 125행 → ≈40행으로 **개선**된다(밴드 사다리 + 거터 축소).

### 9.3 리딩 거터 증가 — SPACE-9의 반대 방향

| | 오늘 | 격자 |
|---|---|---|
| 제목 텍스트 x | 219~265 (p50 241) | **279 고정** |
| 증가 | — | p50 대비 **+38px**, min 대비 +60px |

가장 큰 남은 레버는 좌측 거터 70px(SPACE-6/SPACE-10/RHYTHM-2의 소관)이며, 격자는 거터가 32px로 줄어도 아무것도 깨지지 않는다(`--rail-inset` 변수 기반).
