# 리디자인 방향 B — 「상시 2열 + 브라우즈 상태 복원」

> **설계 명제**: 2열 마스터-디테일은 이미 존재한다 — 선택했을 때만 켜지는 것을 상시로 바꿔, 죽은 폭과 선택 시 리플로우를 동시에 없앤다.

---

## 0. 이 안이 서 있는 단 하나의 실측

| 상태 | 1440 목록 스크롤러 | 행 잉크 우측 끝 | 죽은 우측 폭 |
|---|---|---|---|
| 무선택 (현행) | 1398 | 985 | **412** |
| 행 선택 (현행) | 938 | 935 | **24** |

행 디자인은 **938px 컬럼에 이미 맞다**. 즉 이 화면에는 "넓은 목록"이 존재한 적이 없다 — `Body{max-width:880px}`이 1398px 컬럼에서도 880px만 쓰기 때문에, 무선택 상태의 412px은 **한 번도 쓰인 적 없는 폭**이다.

그래서 상시 2열의 실제 비용은 이것뿐이다:

```
무선택 1440:  Body 880  →  867   (−13px)
              그 대가로 403px 상시 패널을 얻는다
```

**−13px의 잉크로 403px의 패널을 산다.** 이것이 방향 B의 전부이고, 다른 모든 항목은 이 결정에서 파생된다.

파생 결과 3가지:
1. 목록 컬럼 폭이 **선택 여부와 무관한 상수**가 된다 → 선택 리플로우 460px → **0px**, 그리고 컨테이너 쿼리로 밴드를 나눌 수 있는 결정적 폭이 생긴다(ADAPT-3).
2. 폭이 상수이므로 행을 **고정 px 트랙 격자**로 바꿀 수 있다 → 제목/기간/국기 x 고유값 11·157·161 → **각 1종**(ALIGN-1/4/5).
3. 우측 패널이 상시 존재하므로 **행이 짊어지던 조회 부담을 덜 수 있다** → 요약(FiLayers) 버튼 삭제, 액션 열 72→32px, 회수분은 제목 트랙으로.

## 1. 레이아웃 골격

### 1.1 CatalogSplit — 상시 2열 사다리

`apps/web-admin/src/pages/events/styles/layout.styles.ts:182-211` 전면 교체. **`$hasSelection` prop 삭제** — 컬럼 배분이 선택 상태에 의존하지 않는 것이 이 안의 핵심 계약이다.

```
/* ≥1760 — 목록 상한 도달 구간. 남는 폭은 페이지 여백으로 배출 */
grid-template-columns: minmax(0, 1180px) clamp(460px, 30vw, 640px);
gap: 24px;  justify-content: center;

/* 1600–1759 */
grid-template-columns: minmax(0, 1180px) clamp(460px, 30vw, 560px);
gap: 24px;  justify-content: center;

/* 1400–1599 */
grid-template-columns: minmax(0, 1fr) clamp(400px, 28vw, 460px);
gap: 20px;

/* 1200–1399 */
grid-template-columns: minmax(0, 1fr) clamp(340px, 26vw, 400px);
gap: 16px;

/* <1200 — 폴백. 단일 컬럼 + 선택 시 오버레이 드로어(현행 유지) */
grid-template-columns: minmax(0, 1fr);
gap: 0;
```

* `transition: grid-template-columns`는 **삭제**한다. 더 이상 트랙이 변하지 않으므로 트랜지션할 대상이 없다(현행 0.18s 리플로우 애니메이션이 곧 SPACE-2가 지적한 결함 그 자체).
* Aside는 **항상 마운트**된다. 바뀌는 것은 폭이 아니라 **내용(모드 A ↔ 모드 B)**뿐이다.

### 1.3 「2열 끄기」 옵션과 1398px 단일 컬럼

**옵션 제공**: ViewSwitcherRow의 '넓게' 옆 34px 토글(`?aside=off` + localStorage, `aria-pressed`). 기본값은 ≥1200에서 on.

**끈 상태의 규약** — 행이 1398px로 늘어나지 **않는다**:

```
CatalogSection { width: min(100%, 1180px); }     /* 목록 카드 상한 */
PageStyles.ActiveContent > * { max-width: 1180px; }  /* 툴바도 같은 상한 */
```

* 1440 뷰포트에서 2열을 끄면: 카드 1180 → container 1178 → Body 1070 → **XL 밴드**. 제목 624px, 국기 5칩(176px), 액션 32px. 즉 **≥1760 2열과 픽셀 단위로 동일한 행**이 렌더된다.
* 남는 218px은 **카드 밖 페이지 여백**이 된다. 툴바도 같은 상한을 받으므로 툴바 우측 끝과 카드 우측 끝이 한 x에 선다(ALIGN-2의 '단일 우측 기준선'이 카드 레벨에서도 성립).
* **왜 상한을 두는가**: 행의 정보량은 Body 1070px에서 포화한다 — 제목 624px가 252행 중 251행을 전량 노출하고, 국기 5칩이 관련국 4~5개 행 21건을 '+N' 없이 전부 싣는다. 그 위의 픽셀은 전부 열과 열 사이의 공백, 즉 SPACE-1이 지적한 결함 그 자체다. 상한을 두면 그 픽셀은 '깨진 행'이 아니라 '여백'으로 읽힌다.
* 2열을 끈 상태에서 행을 클릭하면 <1200과 동일한 **오버레이 드로어**가 열린다. 클릭 계약(행 클릭 = 상세)이 어떤 설정에서도 깨지지 않는다.

### 1.4 `Body{max-width:880px}` — 제거한다

`event-list-item.tsx:637` 삭제. 폭 소유권을 3층으로 재배치:

| 층 | 소유자 | 값 |
|---|---|---|
| 페이지 | CatalogSplit 트랙 | 1.1의 사다리 |
| 카드 | CatalogSection | `width: min(100%, 1180px)` (1열일 때만 실효) |
| 행 | Body grid 트랙 | 1.2의 밴드별 고정 px + 제목 1fr |

주석 `:631-633`("읽기 컬럼 제한")도 함께 제거 — 실측상 그 상한에 걸려 말줄임되는 제목은 252행 중 1행이었으므로 지키는 것이 없었다.

## 2. Aside — 「탐색/상세」 상시 패널

### 2.1 프레임 (두 모드 공통 — 모드 전환 시 리플로우 0)

```
AsideCard        border-radius 12px, 1px border, 목록 카드와 동일 표면
                 라이트 #ffffff / border rgba(20,19,34,0.08)
                 다크 rgba(255,255,255,0.02) / border rgba(255,255,255,0.07)
                 height 100%, display flex column, overflow hidden
AsideHeader      height 44px (= --century-header-h)  ← 목록 첫 세기 헤더와 수평선 일치
                 padding 0 14px, border-bottom hairline
AsideBody        flex 1, overflow-y auto, padding 14px, gap 18px
                 scrollbar 6px (CompactList와 동일)
```

* 두 모드의 헤더 높이·패딩·스크롤 컨테이너가 **동일**하다. 전환은 `AsideBody` 내용 교체 + `opacity 0→1 120ms`(reduced-motion에서는 없음). **width/height/transform 애니메이션 금지** — 그것이 SPACE-2가 고발한 리플로우다.
* `role="complementary"` `aria-label="사건 탐색"`. 모드 전환 고지는 **기존 `DrawerAnnouncer`(role=status)** 를 그대로 쓴다(A11Y-18 회귀 금지).
* DOM 순서는 현행 유지(목록 → 알림 → Aside). 로빙 tabindex 계약이 목록 안에서 닫혀 있으므로 영향 없음.

### 2.2 모드 A 「탐색」 — 무선택 상태의 403px을 채우는 것

우선순위대로 위에서부터. **모든 블록이 이미 페이지가 들고 있는 상태만 소비한다 — 신규 API 0건.**

#### A0. 헤더
`탐색` 12px/700 letter-spacing .04em metaText · 우측 `단축키 ?` 아이콘 버튼(기존 도움말 모달 재사용).

#### A1. 스코프 요약 (상시)
```
전체 사건  167건
21세기–9세기 · 12개 세기 · 88개 연도
```
* 1행: 15px/700 primary + '건' 12px/500 metaText.
* 2행: 11.5px/500 metaText.
* 필터 중이면 `조건 일치 62건 / 등록 전체 167건(최상위)` — **모수 규약은 `CatalogHeaderStats`와 동일**(IA-13 회귀 금지). 두 곳이 다른 모수를 말하면 안 되므로 같은 props를 받는다.
* 삭제되는 `PageHeader`('사건 연대표')와 `ViewHint`의 정체성/설명 역할을 이 블록이 흡수한다.

#### A2. 적용된 조건 (필터 활성 시에만)
* 라벨 `적용된 조건` 11px/700 tracking .04em metaText.
* 칩: `[카테고리 전쟁/군사 ×] [대륙 아시아 ×] [검색 "조약" ×] [북마크만 ×]`
  12px/500, radius 6px, bg 라이트 `rgba(15,23,42,.05)` / 다크 `rgba(255,255,255,.06)`, 텍스트 secondary. × 버튼 시각 16px / 히트 24px(WCAG 2.5.8).
* 우측 하단 `전체 해제` 11.5px/600 BRAND — 기존 `handleResetAll` 재사용.
* **이 블록이 있어야 하는 이유**: 목록이 짧아진 이유가 상단 툴바에만 있어서, 스크롤을 내린 사용자는 원인을 볼 수 없다. 목록 0건 빈 상태에서도 복구 경로가 눈이 있는 곳에 함께 놓인다.

#### A3. 세기 분포 · 점프 (이 패널의 핵심)
```
21세기  ███████                    30건
20세기  ████████████████████████   93건   ◀ 지금 보는 중
19세기  ██████                     24건
…
 9세기  █                           2건
```
* 데이터 출처 = `buildYearBuckets`가 이미 만드는 **`centuryCount`**. 신규 계산 0. ⚠️ **렌더된 행이 아니라 모집단에서 센다** — 접힘/평탄화 상태에 의존하면 회귀 금지 3항을 깬다.
* 행 22px + gap 2 → 12세기 ≈ 288px. 행 구성: `[라벨 46px 우측정렬 12/600] [막대 flex] [카운트 34px 우측정렬 12/600 tabular]`.
* 막대: height 6px radius 3. 트랙 라이트 `rgba(15,23,42,.06)` / 다크 `rgba(255,255,255,.07)`. 채움 라이트 `rgba(37,99,235,.55)` / 다크 `rgba(147,197,253,.5)`. 폭 = `count / max × 100%`.
  ⚠️ **카테고리 hue 금지** — 색 예산 규약(TYPE-3 canon)상 hue는 카테고리 전용이다. 여기는 단일 브랜드 톤.
* 현재 뷰포트 세기: 라벨 700 + text.primary, 채움 `#2563eb`(라이트)/`#93c5fd`(다크) 솔리드, 좌측 2px 마커.
  판정은 **`CenturySection` 12개를 관찰하는 IntersectionObserver 1개**(`rootMargin: '-44px 0px -70% 0px'`). scroll 리스너 금지, 행별 리스너 금지.
* 행 전체가 버튼. 클릭 → `document.querySelector('[data-century="20"]').scrollIntoView({block:'start', behavior})`. `Stop`/`CenturySection`의 `scroll-margin-top: calc(var(--century-header-h) + 44px)`가 이미 sticky 가림을 처리한다(회귀 금지 4항 재사용).
* **선택을 바꾸지 않는다** — 점프는 위치 이동이지 선택이 아니다. `selectedEventId` 불변 → 모드 A 유지.
* a11y: `<div role="group" aria-label="세기 분포">` 안에 버튼 12개, 각 `aria-label="20세기로 이동 — 93건"`. **로빙 tabindex**(정지점 1개, ↑↓로 내부 이동) — 12개를 전부 탭 정지점으로 두면 회귀 금지 2항의 정신을 어긴다.
* 30화면짜리 스크롤에서 위치와 이동을 동시에 주는 유일한 수단이 된다(SPACE-6이 70px 거터에 넣자고 한 것을, 실제로 폭이 남는 곳에 넣는다).

### 2.3 모드 B 「상세」

* `EventDetailPanel`을 **그대로** 렌더(변경 0). 폭 340~640px는 현행이 이미 지원하는 범위(현행 ≤1400에서 380px).
* 헤더 우측 `×`(닫기) = `clearSelectedEvent` → 모드 A로 복귀. 폭은 그대로.
* `EventDetailPanel`의 `DetailPanelEmpty`("사건을 선택해주세요")는 **딥링크 로딩 전용**으로만 남는다 — 무선택 빈칸은 이제 모드 A가 대신하므로 그 문구가 사실이 아닌 상황이 사라진다.
* 목록 → 상세 이동 시 행의 어떤 좌표도 움직이지 않으므로, "방금 읽던 행의 모양이 클릭 직후 바뀐다"(SPACE-2)가 소멸한다.

## 3. 행 격자

### 3.1 트랙 정의

`Body`를 flex → **grid**. 트랙 폭은 `CompactList`가 정의하는 CSS 변수를 읽는다 — **subgrid 금지**(회귀: `RowList`가 연도 그룹마다 별도 DOM이라 subgrid/auto/max-content는 그룹마다 다른 폭을 만든다). 변수 + 고정 px가 전 그룹 공통 축을 만드는 유일한 방법이다.

```css
/* CompactList (컨테이너) — 밴드별로 여기만 바뀐다 */
container-type: inline-size;
--t-tree: 24px;  --t-date: 46px;  --t-cat: 64px;
--t-dur: 56px;   --t-flags: 128px; --t-act: 32px;
--row-gap-x: 8px;
--indent: clamp(10px, 1.6cqi, 20px);

/* Body */
display: grid;
grid-template-columns:
  [tree]  var(--t-tree)
  [date]  var(--t-date)
  [cat]   var(--t-cat)
  [title] minmax(0, 1fr)
  [dur]   var(--t-dur)
  [flags] var(--t-flags)
  [act]   var(--t-act);
column-gap: var(--row-gap-x);
align-items: baseline;             /* ALIGN-11 */
```
`.cell-tree, .cell-flags, .cell-act { align-self: center }` (픽토리얼·컨트롤 셀).

### 3.4 들여쓰기 · 우측 기준선

* `Stop{margin-left: depth*22px}`(`:466`) **삭제**. 들여쓰기는 **제목 셀 안**으로만 이동 → 날짜·칩·기간·국기·액션이 depth와 무관하게 한 x에 선다(ALIGN-3). depth 1 액션이 부모보다 22px 튀어나오던 결함 소멸.
* `Stop::before/::after`(커넥터·도트)의 `- $depth*22px` 항 제거 → `left: calc(-1 * var(--rail-inset))`로 단순화.
* 들여쓰기 단위 22 → **20px**(= tree 셀 폭 24 − 4, 8px 그리드 정합). depth 2는 40px에 착지(ALIGN-13).
* 우측 기준선 2개로 고정:
  * **잉크 기준선** = act 트랙 우측 = 카드 내부 우측 − 24px. 행 액션·기간·국기·**세기/연도 헤더 카운트**가 전부 여기에 선다(ALIGN-2/14).
  * **규칙선(hairline)** = 카드 내부 우측 − 12px. Stop border-bottom·divider hairline이 여기. 잉크보다 12px 밖 = 좌측 14px 패딩과 대칭.

### 3.5 `tabular-nums`

`Stop{font-variant-numeric: tabular-nums}`(`:481`) **삭제**하고 `Year`·`Duration`·`ChildCountBadge`·`CollapsedCount`·divider 카운트에만 국소 선언. 제목 109/252행(43%)이 숫자를 포함하며 등폭이 폭을 최대 7px 넓히던 손실 회수(ALIGN-10). 우측 정렬 날짜와 짝을 이뤄야 등폭이 비로소 정렬 이득으로 바뀐다.

### 8.2 Aside 스켈레톤

## 10. 회귀 금지 9항 대조

| # | 항목 | 이 안의 취급 | 위협도 |

### 위협 항목별 완화책
* **5항(최고 위험)** — 격자를 `@container (min-width: 620px)` 안에만 선언한다. S 밴드 CSS는 현행 파일에서 **한 줄도 지우지 않는다**. 검증: 320/360/390/480/640px 5폭에서 행 높이 고유값 ≤2 스냅샷.
* **2항** — Aside 진입 시 Tab 정지점 증가를 5 이하로 묶는다(세기 12개=1, 최근 5개=1, 필터칩 N=1, 전체해제 1, 닫기 1). 검증: `document.querySelectorAll('[tabindex="0"], button:not([tabindex="-1"])')` 카운트 전후 비교.
* **3항** — A3 데이터가 `visibleFlattenedHierarchy`가 아니라 `buckets.centuryCount`임을 타입으로 강제(전용 prop `centuryCount: Map<number, number>`만 받고 노드 배열을 받지 않는다).
* **7항** — dur 셀 공유로 인해 `hiddenChildCount>0 && duration!==''`인 행에서 기간이 밀린다. 그 행 수를 사전 측정(현 데이터 추정 <5행)하고, 넘으면 힌트를 act 트랙 앞 아이콘 버튼으로 승격하는 대안을 쓴다.
* **9항** — 억제 조건은 `startPrecision==='day' && endPrecision==='day' && start===end`로 **좁게**. precision 미기록·'year'·'month'는 현행 그대로.

## 12. 이 안이 **해소하지 못하는 것** (정직하게)

* **세로 예산 전부** — 스크롤 17,903px, 연도 헤더 5,500px(31%), 1행짜리 연 그룹 50개, 화면당 9행. 방향 B는 **가로축 재배분**이다. `PageHeader`·`ViewHint` 삭제로 목록 가시 높이 604 → ~681px(화면당 9 → ~10.7행)를 얻지만 그뿐이다. SPACE-3/5/8/11·RHYTHM-1/3/9/10은 손대지 않는다.
* **타입·색 위계** — 칩이 날짜보다 강한 문제(TYPE-1), 다크 도트 3:1 미달(TYPE-2), 카테고리 3중 인코딩(TYPE-3), amber 4중 과부하(TYPE-6), 타입 5단 붕괴(TYPE-10)는 그대로다. 격자는 이 값들에 **중립**이라 나중에 얹을 수 있다.
* **레일의 의미론** — 1년과 203년이 같은 63px(RHYTHM-1), 도트/커넥터 504개 노이즈(RHYTHM-2), stuck 헤더 관통(RHYTHM-4), 세기 헤더 반투명(RHYTHM-5)은 범위 밖.
* **모바일 크롬 415px**(SPACE-7) — Aside가 없는 폭이라 이 안이 줄 수 있는 것이 없다.
* **리딩 거터**(SPACE-9) — 오히려 **악화**된다. 제목 x는 p50 241 → **262px 단일값**으로 21px 뒤로 밀린다. 11종의 계단을 없애는 대가로 지불하는 값이며, M/M2 밴드에서는 거터 축소로 230px까지 회수된다.

## 13. 이 안의 가장 큰 대가 (숨기지 않음)

1. **무선택 시 목록 컬럼이 1398 → 977px로 줄어든다(−30%).** 다만 실제 잉크는 985 → 972px(−13px)이라 체감 손실은 제목 말줄임 1행 → 5행뿐이다. 현행이 그 421px을 이미 버리고 있었다는 사실이 이 거래의 근거 전부다.
2. **행 안 여백은 사라지지 않고 열 사이로 옮겨간다.** 1440 기준 제목 트랙 469px에 중앙값 제목 177px → 292px의 셀 내 공백. 그러나 현행은 행 끝에 412px + 제목↔기간 사이 가변 공백이었고, 무엇보다 새 공백은 **양쪽이 고정 x**라 열로 읽힌다(157종 → 1종). 표를 얻기 위해 지불하는 표준 비용이다.
3. **1200~1319px가 가장 빠듯하다.** M 밴드 제목 364px(말줄임 ~13행). 이 구간을 살리려고 aside를 340px 아래로 내리면 `EventDetailPanel`이 깨지므로 내리지 않는다.
4. **ADAPT-12의 ②(≥1600 기간 레인 240px)는 기각한다.** 초광폭의 남는 폭은 Aside(576px)와 국기 5칩에 쓴다. 목록 행에 시각화 레인을 얹는 것은 타임라인 뷰와 중복이며 flat-list-rows canon(중첩 박스 금지)과도 어긋난다.
5. **Aside는 상시 렌더되는 두 번째 관심 대상이다.** 훑기 중 시선을 뺏지 않도록 모드 A는 전부 무채색 + 단일 브랜드 톤으로 묶고, 애니메이션은 IntersectionObserver의 현재-세기 하이라이트 하나뿐이다.
