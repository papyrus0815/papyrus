## 왜 다시 만들었나

사용자 판정: **"지금 디자인은 버리고 새로 만들어야 한다. 타임라인에 맞게."**

v4(이산 3단 드릴다운)는 화면에 **시간축이 없었다**. 구조가
`스택색 히스토그램` + `기간 밴드` + `평면 리스트`였고, 본문의 9할을 차지하는 리스트는
연도 열이 붙은 표였다. 세로로 읽히는 순간 "연표"가 아니라 "목록"이고, 사용자는 그걸
정확히 짚었다.

v3(연속 가로 축 간트)는 그 전에 이미 폐기된 적이 있다. 그래서 이번 판은 **v3로 되돌아가는
것이 아니라, v3가 무너진 지점을 구조로 제거한 가로 축**이다.

| | v3 간트 | v4 드릴다운 | v6 (현재) |
|---|---|---|---|
| 시간축 | 연속 가로 | 없음(이산 버킷) | **연속 가로** |
| 밀집 해소 | 라벨 배치 알고리즘·클러스터·+N | 드릴로 모수 축소 | **1행 1사건** |
| 스크롤 | 가로+세로+팬+줌 | 세로 | **세로 하나** |
| 코드 | 5,666줄 단일 파일 | 3,940줄 | 약 2,000줄 / 5파일 |

## 원칙

- **P1 x축은 연도에 선형 비례한다.** 1901–1902 사이 거리 = 1991–1992 사이 거리.
  밀집한 시대는 밀집해 보이는 게 맞다(사용자 선택: '실제 시간 비례').
- **P2 한 행에 한 사건.** v3가 무너진 지점은 "여러 사건을 한 레인에 밀어 넣고 라벨 배치
  알고리즘으로 밀집을 푸는 것"이었다. 행을 나누면 **라벨이 겹칠 이웃 자체가 없다.**
  대신 세로로 길어지고, 그건 스크롤 하나가 감당한다.
- **P3 창 소속은 겹침 기준.** 1914~1918 전쟁은 1916년만 보는 창에도 잘린 막대로 남는다.
  시작 기준 소속은 목록 뷰의 규약이지 연표의 규약이 아니다.
- **P4 조작면은 셋, 전부 눈에 보인다.** 범위 막대 드래그 · 축 헤더 드래그 · 버튼
  (전체/‹/›/−/＋). Ctrl+휠 줌·Space 팬 같은 숨은 제스처 없음.
- **P5 인코딩은 셋.** 색=카테고리, x 위치·폭=시간, 막대/점=기간/시점.

[범위 막대]  밀도 실루엣(sqrt) + 현재 창 프레임 + [전체][‹][›][−][＋][모두 접기]

### v6.1 — "여전히 사건 보기가 힘들다"에 대한 답

v6.0은 제목을 막대 옆에 붙였다. 시간 위치는 정직했지만 **읽는 축**이 없었다 — 행마다
제목 시작 x가 달라(1911–1920 창에서 265px ~ 1,290px) 20줄 읽는 데 눈이 가로로 1,000px씩
튄다. 간트 차트가 예로부터 "왼쪽은 표, 오른쪽은 시간"인 이유가 그것이다. 사용자가 짚은
네 가지를 한 판에 고쳤다.

| 지적 | 처방 |
|---|---|
| 제목이 제각각이라 안 읽힘 | **좌측 고정 열**로 분리 — `연도 │ 제목 │ 트랙 │ 관련국` |
| 행이 너무 많아 찾기 힘듦 | **적응형 그룹 + 접기** — 창 폭이 알갱이를 정하고(세기/10년대/연도), 60행을 넘는 창은 접힌 채로 진입한다. 전체 보기 = 세기 13줄 색인 |
| 글자·막대가 작고 흐림 | 행 28→32px · 제목 12→13px · 막대·점 9→12px · 그리드라인 강화 · 행 괘선 추가 |
| 한 사건의 내용을 모름 | 우측 **관련국 열** + hover 툴팁(카테고리 · 관련국 · 설명 180자) |

**열 정의는 CSS 변수 `--tl-cols` 하나가 단일 출처**다. 축 헤더·그리드라인·행이 같은 변수를
쓰므로 세 곳이 각자 폭을 계산하다 축이 밀리는 일이 없다. 좁은 화면에서는 이 변수만 바꾼다
(≤1180px 관련국 열 소멸, ≤640px 연도 열 52px·제목 46%).

### v6.3 — 리스트 영역 키우기

실측이 문제를 그대로 보여 줬다(뷰포트 1000px): 10년 창에서 리스트 영역은 **654px = 19행**,
그중 카드 안 크롬이 **171px**(헤더 41 + 범위 막대 96 + 축 34). 전체 보기에서는 카드가
내용 높이로 쪼그라들어 **아래 273px이 통째로 비었다**.

| 조치 | 효과 |
|---|---|
| 범위 막대를 **한 줄로** — 라벨·개요 트랙·버튼이 같은 행, 전 범위 양끝(800/2099)은 트랙 모서리로 | 96 → 39px |
| 리스트 영역에 뷰포트 파생 `min-height` | 전체 보기 빈 공간 273 → 143px, 축·격자가 화면 끝까지 |
| 상·하한 오프셋 완화(320→290 / 230→210) | 리스트 654 → **706px** |
| **조밀 모드** 토글(행 32→25px, 글자 크기는 유지) | 한 화면 19 → **24행** |

`min-height`는 항상 `max-height`보다 작게 잡는다(CSS에서 min이 max를 이긴다) — 640~1200px
높이 전 구간에서 페이지 오버플로 0을 실측했다.

⚠️ 조밀 모드는 **행 높이만** 줄인다. 글자·막대 크기는 그대로다 — v6.1에서 "글자가 작다"를
고친 걸 되돌리면 안 된다.

### v6.4 — 시각 정리

기능이 자리를 잡은 뒤의 결은 네 군데에 있었다.

- **조작 위계** — 버튼 일곱 개가 전부 같은 무게의 테두리 알약이라 매번 읽어야 했다.
  성격이 같은 시간 이동·배율(`‹ › | − ＋`)은 **한 덩어리**(연결된 세그먼트)로 묶고,
  상태를 바꾸는 텍스트 명령(전체·모두 접기·조밀)은 테두리 없는 **고스트 버튼**으로 한 단계
  내렸다. 켜진 조밀만 primary 색을 쓴다.
- **그룹 머리글** — 캐럿이 연도 열에 떨어져 있어 무엇을 여는 손잡이인지 안 보였다.
  캐럿을 라벨 바로 왼쪽으로 옮기고, 건수는 칩으로, 남는 폭은 괘선이 먹어 섹션 제목처럼 읽힌다.
- **잘린 막대** — 직각으로 뚝 끊기면 '여기서 끝났다'로 읽혀, 1914~1918 전쟁이 1916년 창에서
  1916년에 끝난 것처럼 보였다. 창 밖으로 이어지는 끝을 `mask-image`로 **흐리며 끊는다**.
- **표와 차트의 경계** — 경계선 하나로는 둘이 같은 표의 연속으로 읽혔다. 트랙 열에 아주 옅은
  바탕(1.5%)을 깔고, 내용이 짧아도 격자가 영역 끝까지 내려오게 했다(`min-height: 100%`) —
  전체 보기는 12줄뿐이라 그 공백이 화면의 4분의 1이었다.

부수적으로 총건수는 칩으로, 범례는 한 단계 조용하게(10.5px·tertiary, hover에서 또렷),
열 이름은 자간을 벌려 눈금 숫자와 성격을 갈랐고, 개요 막대의 현재 창에는 **양끝 손잡이**를
붙여 '끌 수 있는 것'임을 보이게 했다. 행 hover 시 막대·점에 카테고리 색 20% 링이 돈다.

### v6.5 — 상자 해제 · 선 걷어내기

사용자 판정: **"지금 박스 안에 리스트가 있는데, 박스 안으로 가두지 마라."** 그리고
"선이 너무 많다 · 글자가 작고 회색이다 · 상단이 복잡하다 · 색이 지저분하다".

**상자 해제가 근본**이었다. 타임라인만 테두리·라운드·배경을 가진 카드였고(목록 뷰
`CompactList`는 카드가 없다), 그래서 ⑴ 지면 위에 뜬 위젯처럼 보이고 ⑵ 카드 안에서 다시
스크롤이 생기며 ⑶ 높이를 `calc(100dvh - 320px)` 같은 **어림 상수**로 맞춰야 했다.
카드 크롬을 걷고 `flex: 1; min-height: 0`만 두니 활성 영역이 주는 만큼 정확히 쓴다
(리스트 706 → 721px, 헤더 41 → 28px, 640~1200px 전 구간 오버플로 0).

걷어낸 선: 카드 테두리 · 행 괘선 · 트랙 경계선 · 그룹 머리글 상하선 · 잔눈금 격자선
(굵은 눈금만 남김) · 그룹 라벨의 leader line. 표와 차트는 이제 **선이 아니라 바탕 톤**
(2%)으로 갈린다.

타이포: 제목 13 → **14.5px**, 연도 12 → 12.5px, 관련국 tertiary → **secondary**,
그룹 라벨 12.5 → 13.5px, 행 높이 32 → 34px(조밀 25 → 26px).

상단: 카드 제목 '사건 타임라인'을 **삭제**했다 — 툴바의 뷰 세그먼트가 이미 그렇게 말하고
있어 같은 말을 두 번 하고 있었다.

⚠️ 상자를 걷은 뒤 `RowsRoot`에 `min-height: 100%`를 두면 안 된다 — 카드 안에서는 '덜 그려진
표'를 막아 줬지만, 지면 높이를 다 쓰는 지금은 마지막 행 아래 수백 px이 빈 차트 캔버스가 된다.

**접힌 그룹도 트랙에 분포 점을 남긴다** — '접었더니 아무것도 안 보인다'가 되지 않게.
점은 최대 80개까지(그 이상은 건수가 더 정확하다).

**좌측 열은 연속 중복을 통합한다** — 1903이 여섯 줄 이어지는 표는 같은 사실을 여섯 번
말한다. 값은 구간 **첫 행에만** 쓰고, 이어지는 행은 병합 괘선(첫 행 글자 아래에서 시작해
마지막 행 글자 높이에서 끝나는 세로 실선)만 남긴다. 접힌 행도 값 자체는 들고 있어
접근성 이름·툴팁에서는 사라지지 않고, 통합은 **그룹 경계에서 끊긴다**(그룹이 바뀌면
한 번은 다시 말한다). 연도 그룹에서는 판정 단위가 월·일이라 같은 날짜만 접힌다.

**좌측 열의 값은 그룹 알갱이가 정한다** — 연도 그룹에서는 월·일(`4.27`), 그보다 넓으면 연도.
단 **그 그룹의 해에 시작한 사건일 때만** 월·일을 쓴다. 1898년에 시작해 1911년 그룹에 들어온
사건에 '4.10'만 찍으면 몇 년인지가 사라진다.

⚠️ **관련국은 `countries`가 아니라 `relatedCountries`/`relatedHistoricalCountries`에 있다.**
목록 transformer(`eventTransformers.ts:131`)가 `countries: []`를 하드코딩하고 관련국을 이
두 필드로 싣는다 — `countries`만 읽으면 실데이터에서 항상 빈 값이다.

## BC 좌표 규약

연도 0은 존재하지 않는다(1 BC 다음이 AD 1). 축 좌표는 `toAxisYear`로 BC 쪽을 한 칸 당겨
연속선으로 만든다: `… -2 → -1, -1 → 0, 1 → 1 …`. 이 보정을 빼면 BC↔AD를 걸치는 창에
1년 폭의 유령 간격이 생긴다. `toYear`는 **양끝 포함**이라 축 구간은 `toAxisYear(toYear) + 1`
에서 끝난다(1914~1914 = 폭 1년).

## URL (`tlw`)

정본은 **연도 구간** `y1901..2000`(BC는 음수 `y-100..-1`), 일자 미상 창은 `u`.
구분자가 `..`인 이유: `URLSearchParams`는 `A-Za-z0-9*-._`만 그대로 두므로 `:`·`~`를 쓰면
주소창에 `y1801%3A1900`으로 박힌다. 사람이 읽고 손으로 고칠 수 있는 축이라 인코딩되지
않는 문자만 쓴다.

v4 토큰 `c19`·`d1871`은 **읽기만** 계속 지원한다(배포된 딥링크를 죽이지 않는다). 되쓰기는
항상 새 문법이라 첫 write에서 `y1801..1900`으로 정규화된다 — URL이 두 문법을 오래 끌고 가지 않는다.
