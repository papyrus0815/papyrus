# 스키마 설계 검토 — 행정기구·행정부처·조직

행정기구(Organization), 행정부처(AdministrationDepartment), 부처 사건(AdministrationDepartmentEvent) 및 연관 도메인을 검토한 결과와, 스키마에 **추가를 고려할 만한 항목**을 정리했습니다.

---

## 1. Organization (조직) 도메인

### 1.1 현재 구조 요약

- **Organization**: name, shortName, localName, type, scope, description, foundedDate, dissolvedDate, websiteUrl, logoUrl, ideology, headquartersCityId, countryId, historicalCountryId, extra
- **OrganizationCountryMembership**: 조직–국가 멤버십(회원/옵서버/창립국 등), startDate/endDate
- **OrganizationHierarchy**: 조직 간 상하/제휴 관계, relationType, startDate/endDate
- **OrganizationPersonRole**: 조직–인물 역할(의장, 사무총장 등), termNumber, startDate/endDate
- **OrganizationAlias**: 별칭/약칭/과거명, type, languageCode, startDate/endDate

### 1.2 추가 검토 항목

| 항목 | 설명 | 우선순위 |
|------|------|----------|
| **설립/해체 날짜 정밀도** | `foundedDate`/`dissolvedDate`가 `DateTime`이라 “년만 알 때”는 일부 비정규 저장이 필요할 수 있음. Event 도메인처럼 `startDatePrecision`/`endDatePrecision`(year/month/day)을 두면 연도·연월·일 단위 표현이 명확해짐. | 중 |
| **조직 상태(enum)** | 해체 여부를 “해체일 존재 여부”로만 보는 대신, `status OrganizationStatus?`(ACTIVE / DISSOLVED / MERGED / SUSPENDED 등)를 두면 목록/필터/표시 로직이 단순해질 수 있음. | 낮음 |
| **조직별 “사건” 타임라인** | 부처에만 `AdministrationDepartmentEvent`가 있고, 조직(Organization)에는 “설립·해체·중요 사건”을 시간순으로 남기는 테이블이 없음. `OrganizationEvent`(organizationId, title, description, startDate, endDate, eventType 등)를 두면 만철·관동군 같은 조직의 연혁을 사건 단위로 쌓을 수 있음. | 높음 |
| **다국가 소속** | 현재 Organization은 `countryId` 또는 `historicalCountryId` **단일** 소속. 국제기구·동맹은 **여러 국가**와 관계를 가짐. 이미 `OrganizationCountryMembership`으로 “멤버십”은 다대다 가능. 단, UI에서 “주 소속 1개”만 쓰고 있다면, 멤버십과 주 소속 역할 구분을 인덱스/뷰나 문서로 정리해 두는 것이 좋음. | 정보만 (스키마는 이미 지원) |

## 2. AdministrationDepartment (행정부처) 도메인

### 2.1 현재 구조 요약

- **AdministrationDepartment**: countryId, parentId, categoryId, name, thumbnailUrl, description, establishedDate, abolishedDate, successorId (후신 1개)
- **AdministrationDepartmentCategory**: name, nameEn (전세계 공통 카테고리)
- **AdministrationDepartmentEvent**: departmentId, title, description, startDate, endDate, eventType, background, aftermath, thumbnailUrl

### 2.2 추가 검토 항목

| 항목 | 설명 | 우선순위 |
|------|------|----------|
| **historicalCountryId** | 현재 부처는 **현대 국가(Country)** 에만 연결됨(`countryId`만 존재). “조선의 6조”, “일본 제국 시대 부처” 등 **역사적 국가(HistoricalCountry)** 단위 부처를 넣으려면 `historicalCountryId String? @map("historical_country_id")`를 추가하는 설계가 필요함. 현대/역사 통합 조회는 애플리케이션 레이어에서 countryId vs historicalCountryId 구분으로 처리 가능. | 높음 |
| **설립/폐지일 정밀도** | Event와 동일하게 `establishedDatePrecision`, `abolishedDatePrecision`(year/month/day)을 두면 “1920년 설립”처럼 연도만 있는 경우를 정규하게 저장할 수 있음. | 중 |
| **카테고리 정렬/표시 순서** | `AdministrationDepartmentCategory`에 `sortOrder Int?` 또는 `rank Int?`를 두면 UI에서 국방·외교·재정 등 표시 순서를 고정할 수 있음. | 낮음 |
| **부처 약칭/영문명** | `name` 외에 `shortName String?`, `nameEn String?`가 있으면 표·다국어 UI에서 유리함. | 낮음 |
| **전신 부처 복수** | 현재는 후신(successorId) 1개만 있음. 한 부처가 “여러 부처를 통폐합”해 만들어지는 경우(예: A+B+C → D)를 명시적으로 넣으려면 `predecessorIds` 같은 다대다 관계 테이블(AdministrationDepartmentPredecessor)을 도입할 수 있음. 대부분은 후신만으로 역추적 가능하므로, 필요 시에만 검토. | 낮음 |

## 3. AdministrationDepartmentEvent (부처 사건)

### 3.1 현재 구조

- title, description, startDate, endDate, eventType, background, aftermath, thumbnailUrl

### 3.2 추가 검토 항목

| 항목 | 설명 | 우선순위 |
|------|------|----------|
| **날짜 정밀도** | Event처럼 `startDatePrecision`, `endDatePrecision`(year/month/day)을 두면 “1923년” 단위 사건 표현이 명확해짐. | 중 |
| **사건–사건/문서 연결** | 나중에 “이 부처 사건이 Event(역사적 사건) 또는 Reference(문서)와 연결된다”는 요구가 생기면, `eventId` 또는 `referenceId` 같은 FK를 추가하는 방안을 검토할 수 있음. | 낮음 |

---

## 4. OrganizationAlias / OrganizationCountryMembership

### 4.1 OrganizationAlias

- 이미 type(ACRONYM/ALIAS/FORMER_NAME/LOCAL_NAME), languageCode, startDate/endDate 지원. **추가 필드 필요성은 낮음.**

### 4.2 OrganizationCountryMembership

- role, startDate, endDate, notes 있음. “가입/탈퇴 사유”를 코드화하려면 `membershipStatus` 또는 `withdrawalReason` 같은 enum/필드를 나중에 검토할 수 있음. **당장 필수는 아님.**

---

## 5. GovernmentPositionDefinition 연계

- `organizationId`, `administrationDepartmentId`로 조직/부처와 직위가 연결됨. **역사적 국가** 전용 직위를 쓰려면, 직위 정의에 `historicalCountryId`를 두는 설계도 가능하나, 현재는 국가/역사국가가 Tenure 쪽에만 있어도 동작 가능. **스키마 추가는 요구가 명확해질 때 검토.**

---

## 6. 권장 적용 순서 (스키마 변경 시)

1. **AdministrationDepartment.historicalCountryId** (선택)  
   - 역사적 국가 단위 부처가 필요할 때 추가.
2. **OrganizationEvent** (선택)  
   - 조직(만철·관동군·총독부 등) 연혁을 사건 단위로 쌓고 싶을 때 새 모델 추가.
3. **날짜 정밀도**  
   - Event와 동일하게 Organization/AdministrationDepartment/AdministrationDepartmentEvent에 `*Precision` 필드를 두면 연도·연월 단위 데이터가 깔끔해짐.
4. **AdministrationDepartmentCategory.sortOrder**  
   - 카테고리 표시 순서를 DB에서 관리하고 싶을 때 추가.

위 항목들은 “반드시 지금 추가해야 할” 필수 사항이라기보다, **도메인 확장·정교화 시 선택적으로 검토**하면 되는 수준입니다.  
필요한 것부터 마이그레이션 계획에 넣어 적용하는 것을 권장합니다.
