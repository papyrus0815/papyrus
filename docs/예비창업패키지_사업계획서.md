# Papyrus 예비창업패키지 사업계획서

> **Papyrus**: 역사적 사건·인물·관계를 체계적으로 관리·시각화하는 지식 그래프 플랫폼
> 
> 본 문서는 Papyrus 프로젝트를 기반으로 한 예비창업패키지 사업계획서이며, **Web-Admin(관리자 대시보드)** 기능을 중심으로 서비스를 상세히 설명합니다.

---

## 창업아이템 개요

### 창업아이템명

**관계 기반 지식 그래프 기술이 적용된 역사적 사건·인물·관계 통합 관리·시각화 기능의(교육·연구·콘텐츠 제작 효율화 및 능동적 지식 창조 혜택을 제공하는) B2B SaaS 플랫폼**

*(요약)* 지식 그래프 기술이 적용된 역사 통합 관리·시각화 서비스

---

### 산출물 (협약기간 내 목표)

**양식 기재용 (그대로 복사 가능)**

- 모바일 어플리케이션(0개), 웹사이트(2개), API 서버(1개)
- 웹사이트: Web-Admin(관리자 대시보드) 1개, Web-User(사용자 포털) 1개

**상세**

| 구분 | 형태 | 수량 | 비고 |
|------|------|------|------|
| 웹사이트 | Web-Admin (관리자 대시보드) | 1개 | 사건·인물·국가·조직 등 구조화 입력·CRUD·연대표·대시보드 |
| 웹사이트 | Web-User (사용자 포털) | 1개 | 큐레이션·탐색·좋아요·댓글 |
| API 서버 | RESTful API | 1개 | NestJS·Prisma 기반, 전 도메인 CRUD·인증 |
| 모바일 어플리케이션 | — | 0개 | 협약기간 내 웹 반응형으로 대응 |

**협약기간(약 8개월) 내 제작·개발 완료할 최종 생산품**

- Web-Admin UX 고도화(입력 폼·검색·필터·품질 도구)
- Web-User 모바일 반응형·기본 분석 강화
- 과금·구독 시스템 구축
- 파일럿 1~2곳 운영 완료, 유료 고객 3~5곳 확보

## 1. 문제인식

### 1-1. 창업아이템 배경 및 필요성

#### 1-1-1. 사회·시장적 맥락

**(1) 디지털 전환과 지식 구조화 요구**

- 2020년대 코로나 이후 교육·문화 분야 디지털 전환이 가속화되며, **구조화된 데이터 기반 콘텐츠** 수요가 급증하고 있습니다.
- 국사편찬위원회, 한국학중앙연구원, 각종 박물관·아카이브가 디지털 아카이브를 확대하고 있으나, **플랫폼 간 연계·통합이 부재**하여 데이터 재활용성이 낮습니다.
- 교육부·KERIS의 스마트교육 추진에 따라 **역사 교과 디지털 자료**에 대한 체계적 관리 체계 요구가 증가하고 있습니다.

**(2) AI·검색 시대의 지식 그래프 수요**

- ChatGPT, 검색 엔진 등은 **구조화된 지식 그래프(Knowledge Graph)** 를 기반으로 정확한 답변·추천을 제공합니다. 역사 분야는 관계 데이터(인물–사건–국가 등)가 부족해 AI 활용이 제한적입니다.
- Wikipedia, Wikidata 등 글로벌 플랫폼은 역사 도메인에 특화된 **입력·검증 워크플로우**가 미흡하여, 전문 연구자·교육기관이 활용하기 어렵습니다.
- 국내·해외 교육·미디어 기관은 **시공간 기반 연대표·지도 시각화**가 통합된 데이터 소스를 찾고 있습니다.

#### 1-1-2. 기존 서비스별 한계(구체적 문제)

역사·지식 정보를 다루는 기존 서비스들은 다음과 같은 구조적 한계를 가집니다.

**나무위키·위키피디아**

| 한계 | 구체적 현상 |
|------|-------------|
| 정보 파편화 | "트럼프 관세 정책", "미중 무역전쟁", "중국 WTO 가입" 등이 개별 문서로 분산 → 관계 파악을 위해 수십 개 문서를 일일이 탐색해야 함 |
| 비구조화된 자유 형식 | 문서마다 작성 방식이 달라 일관성 없음 → 데이터 추출·분석 불가, 관계 정보가 텍스트 속에 묻힘 |
| 시간적 맥락 부재 | 사건들의 시간순 연결이 어려움 → 인과관계 추적 불가, 타임라인 시각화 없음 |
| 검색 기반 네비게이션 | 우연히 찾은 정보만 습득 → "이 사건과 관련된 다른 사건은?" 답을 찾기 어려움 |

**뉴스·미디어·포털**

| 한계 | 구체적 현상 |
|------|-------------|
| 최신 정보만 제공 | 역사적 배경 부재 → "왜 이렇게 되었나?"에 대한 답 없음 |
| 단편적 보도 | 개별 사건만 다룸, 복잡한 관계 설명 부족 |

**학술 데이터베이스**

| 한계 | 구체적 현상 |
|------|-------------|
| 전문가 전용 | 일반인 접근 어려움, 비싼 구독료 |
| 검색 중심 | 탐색 기능 부족, 시각화 미비 |
| 읽기만 가능 | 사용자가 기여할 수 없음, 수동적 소비만 가능 |

**노션(Notion) 등 범용 도구**

| 한계 | 구체적 현상 |
|------|-------------|
| 역사 도메인 비특화 | 사건·인물·국가 템플릿 없음, 데이터 구조를 직접 설계해야 함 → 초기 셋업에 수십 시간 소요 |
| 제한적 시각화 | 테이블/보드뷰만 지원 → 관계 네트워크 그래프·타임라인·교전국 관계도 등 없음 |
| 수동적 관계 연결 | 모든 관계를 일일이 수동 설정 → 자동 연결 기능 없음 |
| 협업·공유 한계 | 개인/소규모 팀용 → 대규모 기관·데이터 표준화에 부적합 |

> **비유**: "노션으로 역사 DB 만들기 = 엑셀로 ERP 만들기" — 할 수는 있으나 엄청난 시간·노력 필요, 결과물은 불완전. 전문 시스템이 답.

**기존 서비스 공통 한계 요약**

- **정보 파편화**: 관련 정보가 수백 개 문서/페이지에 분산
- **비구조화된 데이터**: 위키 등은 자유 형식으로 체계적 분석·추출 불가
- **관계 파악 어려움**: 사건-인물-국가-조직 간 복잡한 관계를 직관적으로 이해하기 어려움
- **시간적 흐름 추적 곤란**: 역사적 사건의 원인·결과를 시계열로 추적 어려움
- **수동 연결의 한계**: 하이퍼링크만으로는 복잡한 관계 표현 불가
- **교육용 활용 제한**: 기존 자료는 교육/연구 목적의 체계적 활용에 한계
- **시각화 부재**: 텍스트 중심으로 복잡한 관계를 시각적으로 이해하기 어려움

#### 1-1-3. 근본적 문제: 수동적 정보 소비

기존 서비스들의 공통점은 **정보를 "보기만" 하는 수동적 경험**입니다.

- **나무위키**: 자유 편집이지만 체계 부재, 내 기여가 다른 문서에 묻힘, 관계 시각화 불가, "내가 만든 지식 세계" 느낌 없음
- **AI(ChatGPT)**: 일방적 질문-답변 관계, 내가 데이터를 쌓을 수 없음, 내 지식이 휘발됨, 생산의 즐거움 없음
- **학술 DB**: 읽기만 가능, 기여·참여 불가

#### 1-1-4. Papyrus의 혁신적 해결 방안

Papyrus는 위 한계를 **구조화·자동화·시각화**로 극복합니다.

| 문제 영역 | Papyrus 해결 방안 |
|-----------|-------------------|
| **정보 파편화** | 통합 데이터베이스 — 사건·인물·국가·조직을 한 시스템에 연결, "이 사건과 관련된 모든 것"을 즉시 표시 |
| **비구조화** | 구조화된 데이터 — 모든 사건이 동일 형식으로 저장, 관계를 명시적으로 관리, 검색·필터·분석·API 연동 가능 |
| **수동 관계** | 자동 관계 연결 — 사건 등록 시 관련 인물/국가 자동 연결, 양방향 네비게이션(사건↔인물↔국가) |
| **시각화 부재** | 다양한 그래프·차트 — 사건 관계 네트워크, 타임라인, 교전국 관계도, 인물 관계도, 통계 차트 |
| **시간 맥락 부재** | 시계열 타임라인 — 인과관계 자동 표시, 역사적 배경 자동 연결, "왜 이렇게 되었나?"에 대한 답 |
| **검색만 가능** | 통합 검색·탐색 — 전역 검색 + 관계 기반 탐색(관련 사건 자동 추천) + 카테고리/연도/국가 필터 |

#### 1-1-5. Papyrus 핵심 가치: 능동적 지식 창조의 즐거움

Papyrus는 **"보기만" 하는 수동적 경험**이 아닌, **"만들어가는" 능동적 경험**을 제공합니다.

| 가치 | 구체적 경험 |
|------|-------------|
| **데이터를 심는 즐거움** | 사건 등록 시 관련 인물·장소·카테고리 지정 — 정원사가 식물을 심듯 내 손으로 역사를 정리하는 보람 |
| **관계가 자라나는 즐거움** | 사건 등록 → 관련 사건 자동 연결, 인물 페이지 자동 갱신, 타임라인·관계 그래프 자동 확장 — "내가 심은 데이터가 살아 움직이는 지식 네트워크" |
| **시각화되는 즐거움** | 입력할수록 관계 그래프·타임라인·통계 차트가 풍부해짐 — 마치 게임 레벨업처럼 "내 지식 세계 성장" 모습을 확인 |
| **공유하는 즐거움** | 정리한 역사를 학생·연구자·일반인이 학습·연구·교양 자료로 활용 — 집단 지성의 일부가 되는 자부심 |
| **전문가가 되는 즐거움** | 특정 주제(한국전쟁, 중동 분쟁 등)에 집중 정리 → 그 분야 데이터베이스 구축자로서 전문성 구축 |

**경험 비교**

| 측면 | 나무위키 | AI (ChatGPT) | Papyrus |
|------|---------|--------------|---------|
| **역할** | 편집자 | 질문자 | **창조자** |
| **경험** | 문서 수정 | 대화 | **지식 세계 구축** |
| **결과물** | 개별 문서 | 휘발성 답변 | **영구 데이터베이스** |
| **시각화** | 없음 | 없음 | **실시간 그래프** |
| **보람** | 문서 1개 개선 | 답변 받음 | **관계 네트워크 성장** |
| **공유** | 누군가 읽을 수도 | 내 대화만 | **모두가 활용** |

#### 1-1-6. 구체적 문제 사례

**사례 1: "미중 무역전쟁을 이해하려면?"**

| 방식 | 소요 시간 | 결과 |
|------|-----------|------|
| **나무위키/위키피디아** | "미중 무역전쟁" → "트럼프" → "중국 경제" → "WTO" → "냉전" 문서 순차 탐색, **약 2시간** | 여전히 파편적 이해 |
| **Papyrus** | "미중 무역전쟁" 사건 1건 조회 → 배경·선행·병행 사건 자동 연결 시각화(중국 WTO 가입, 닉슨 방문 등) → 타임라인·관련 인물 자동 표시, **약 10분** | 구조화된 이해 |

**사례 2: "이순신 장군의 생애를 연구하려면?"**

| 방식 | 과정 | 결과 |
|------|------|------|
| **기존** | "이순신" 문서 + 개별 전투(한산도, 명량 등) + "조선 수군" + "임진왜란" 각각 검색 | 정보가 흩어져 전체상 파악 어려움 |
| **Papyrus** | 이순신 인물 페이지 1곳에서 참여 전투 목록·시간순 타임라인·소속 조직·동시대 인물 관계 **자동 통합** | 통합된 뷰에서 전체 맥락 이해 |

**사례 3: "임진왜란을 Papyrus로 정리한다면?"**

```
1. "임진왜란" 사건 등록 (시작일·종료일·장소)
2. 주요 전투(한산도 대첩, 명량 해전 등) 하위 사건 추가 → 타임라인에 자동 배치
3. 관련 인물 선택(이순신, 선조, 도요토미 히데요시 등) → 각 인물 페이지에 자동 연결
4. 교전국 설정(조선 vs 일본, 명나라 지원) → 교전국 그래프 자동 생성
5. 결과: 임진왜란 상세 페이지 + 이순신 페이지 전투 목록 + 조선-일본 관계 그래프 + 1592-1598 타임라인 완성

→ "내가 임진왜란 데이터베이스를 만들었다!" — 학생·연구자 모두 활용 가능
```

#### 1-1-7. Papyrus 필요성 종합

| 해결 영역 | Papyrus 제공 가치 | 필요성 근거 |
|-----------|-------------------|-------------|
| **통합 데이터 모델** | 현대·역사적 국가, 인물, 사건, 조직, 왕조, 역대 수반, 행정구역을 일원화된 스키마로 관리 | 분산된 데이터의 단일 소스(SSOT) 구축, API·재사용 가능 |
| **전문가 입력 체계** | Web-Admin을 통한 구조화 입력·검증 | 연구자·편집자 생산성 향상, 데이터 품질 보장 |
| **시공간 시각화** | 국가별 대시보드, 연대표, 역대 수반, 행정구역·지도 뷰 | 교육·콘텐츠 제작 효율화 |
| **능동적 경험** | 데이터 심기·관계 성장·시각화·공유·전문가 되는 즐거움 | 수동적 소비 탈피, 지식 기여·창조의 보람 |
| **B2B2C 생태계** | Admin 데이터 → User 포털 큐레이션·API | 수익화·생태계 확장 동시에 교육·연구 공익 기여 |

**필요성 요약**

- **교육·연구**: 구조화된 역사 데이터로 교과서·강의·연구 자료 제작 효율화, 디지털 교육 정책 부합  
- **콘텐츠·미디어**: 관계 기반 탐색·시각화로 교육·다큐멘터리 제작, OTT·유튜브 수요 대응  
- **문화유산·공공**: 한국사·세계사 통합 아카이브, 디지털 휴먼니티 정책 연계  
- **사용자 경험**: 수동적 정보 소비에서 능동적 지식 창조로 전환 — "만들어가는 즐거움"

#### 3-2-2. Go-to-Market 실행 계획

**(1) 1단계: 파일럿 및 검증(0~4개월)**

- **목표**: 제품-시장 적합성(PMF) 검증, 파일럿 사례 확보
- **액션**:  
  - 교육·역사 콘텐츠 1~2곳 무상/저가 파일럿 계약  
  - 실제 데이터 입력·피드백 수집, 개선 반영  
  - 파일럿 결과를 사례 스토리로 문서화(성과·절감 효과)

**(2) 2단계: 초기 상용화(4~8개월)**

- **목표**: 유료 고객 3~5곳, 월 반복 매출(MRR) 확보
- **액션**:  
  - 유료 플랜(Pro) 출시, 파일럿 고객 전환 유도  
  - 교육 박람회·역사 학회·스타트업 데모데이 참가  
  - 1:1 직접 영업 20곳 이상 접촉, 제안서·데모 제공

**(3) 3단계: 확장·다각화(8~12개월~)**

- **목표**: 고객 10곳 이상, 데이터 라이선스·공공 과제 수주
- **액션**:  
  - 데이터 패키지·API 상용화, 라이선스 1~2건 체결  
  - 국사편찬위원회·한국학중앙연구원 등 MOU·과제 신청  
  - 초기창업패키지·창업도약패키지 등 후속 지원사업 검토

- **오픈·협업**: 일부 오픈 데이터·커뮤니티로 생태계 확장, 신뢰 구축

- **나무위키·위키피디아**: 정보 파편화, 비구조화, 시각화·시간 맥락 부재 → Papyrus는 통합 DB·자동 관계·타임라인·그래프로 차별화

- **AI(ChatGPT)**: 휘발성, 기여 불가 → Papyrus는 영구 DB·창조·실시간 그래프

- **확장 가능 아키텍처**: FSD, 도메인 분리, API 버저닝으로 고객 수요 대응
- **최신 스택**: Vite 7, React 19, NestJS 11 등으로 유지보수·성능 우수

- **시공간 시각화**: 연대표·지도·대시보드·통계로 교육·콘텐츠 제작에 직결

**(3) 시장 진입 역량**

- **B2B 포지셔닝**: 교육·연구·콘텐츠·공공 등 명확한 타깃
- **정책 부합**: 디지털 교육, 문화유산 디지털화, 스마트교육 등 정부 정책과 연계
