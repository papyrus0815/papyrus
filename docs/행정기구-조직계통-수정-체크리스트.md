# 행정기구·조직계통 등록을 위한 수정 체크리스트

국가별·시대별로 다른 행정기구를 등록하고, 조직 계통(상하/계층)을 등록할 수 있도록 하기 위해 **어떤 부분을 수정해야 하는지** 정리한 문서입니다.

---

## 1. 현재 스키마 요약

### 1.1 이미 있는 것

| 구분 | 위치 | 내용 | 한계 |
|------|------|------|------|
| **조직** | `organization.prisma` | `Organization` – 이름, 유형, countryId, **historicalCountryId**, 설립/해산일 등 | 행정기구는 `type = GOVERNMENT_AGENCY` 등으로 등록 가능. **현대·역사적 국가 모두** 소속 가능. |
| **조직 계통** | `organization.prisma` | `OrganizationHierarchy` – parent/child 조직, **startDate/endDate**(기간), `OrganizationRelationType` (SUBSIDIARY, COMMITTEE 등) | **조직 간 상하·계층** 및 **시대별 관계 변경** 이미 표현 가능. |
| **행정 부서** | `country.prisma` | `AdministrationDepartment` – name, **parentId**(계층), countryId | **현대 국가(Country) 전용**. 역사적 국가(조선 등) 미지원. |
| **관직 정의** | `government.prisma` | `GovernmentPositionDefinition` – title, positionType, **departmentName**(문자열), countryId/historicalCountryId | 부서는 **문자열**뿐. 어떤 “조직/부처” 소속인지 **엔티티로 연결되지 않음**. |

### 1.2 정리

- **조직 등록 + 조직계통**: `Organization` + `OrganizationHierarchy` 만으로 이미 가능 (국가·역사적 국가 모두).
- **역사적 국가의 “행정기구”**: `Organization`(historicalCountryId)으로 등록 가능. `AdministrationDepartment`는 Country만 있어 조선 등은 불가.
- **직위 ↔ 행정기구 연결**: `GovernmentPositionDefinition`에 부서/조직 FK가 없어, “이 관직이 소속된 기구”를 구조적으로 연결할 수 없음.
- **인물 공무원 경력**: `GovernmentCareer`(person.prisma)는 **countryId 필수, historicalCountryId 없음** → 현대 국가(Country)만 지원. 조선 등 역사적 국가의 관직 경력은 현재 스키마로는 불가(역대 수반은 Tenure로만 가능).

## 2. 수정이 필요한 부분 (체크리스트)

### 2.1 스키마 (Prisma)

| # | 항목 | 파일 | 수정 내용 | 우선순위 |
|---|------|------|-----------|----------|
| 1 | **역사적 국가 행정 부서** | `country.prisma` | `AdministrationDepartment`에 `historicalCountryId`(nullable) 추가. `countryId`를 nullable로 바꾸거나, 현대/역사 둘 중 하나만 쓰도록 제약. | 중 (역사적 국가 전용 “행정 부서” 테이블을 쓰고 싶을 때) |
| 2 | **직위 ↔ 조직/부서 연결** | `government.prisma` | `GovernmentPositionDefinition`에 `organizationId`(Organization FK, nullable) 또는 `administrationDepartmentId`(nullable) 추가. 기존 `departmentName`은 유지해도 됨(표시용). | 높음 (직책이 “어느 기구 소속”인지 명시할 때) |
| 3 | **조직 유형** | `organization.prisma` | 행정기구 구분이 더 필요하면 `OrganizationType`에 예: `HISTORICAL_GOVERNMENT_ORG` 등 추가. 없으면 `GOVERNMENT_AGENCY`만으로도 가능. | 낮음 |
| 3-1 | **Organization 인덱스** | `organization.prisma` | `Organization`에 `historicalCountryId` 인덱스 없음. 역사적 국가별 조직 목록 쿼리 시 `@@index([historicalCountryId])` 추가 권장. | 낮음 |

**참고**:  
- “조직 등록 + 조직계통”만 필요하면 **스키마 추가 없이** `Organization`(GOVERNMENT_AGENCY) + `OrganizationHierarchy`만으로 구현 가능.  
- “역사적 국가도 **AdministrationDepartment**로 관리하고 싶다”면 ① 필요.  
- “관직 정의에서 **소속 행정기구를 FK로 선택**하고 싶다”면 ② 필요.

## 3. 권장 방향 (요약)

- **“조직을 등록하고 조직계통을 등록한다”**  
  → **Organization** + **OrganizationHierarchy** 사용.  
  → 국가·역사적 국가 모두 `Organization.countryId` / `historicalCountryId`로 소속 지정.  
  → 스키마 변경 없이 API·UI만 추가/확장하면 됨.

- **“현대 국가는 행정 부서(AdministrationDepartment)로도 관리하고 싶다”**  
  → AdministrationDepartment API 구현(4) + 필요 시 계층 조회.  
  → 역사적 국가까지 부서 테이블을 쓰고 싶으면 스키마(1) 적용.

- **“관직이 소속된 행정기구를 엔티티로 연결하고 싶다”**  
  → GovernmentPositionDefinition에 **organizationId**(또는 administrationDepartmentId) 추가(2) 후, API·폼(10)에서 선택 가능하게.

이 체크리스트대로 순서 정해서 수정하면, 국가마다 다르고 시대별로 다른 행정기구와 조직계통을 등록·관리할 수 있습니다.

## 4. 추가로 확인한 점 (참고)

- **OrganizationAlias**: 조직의 과거명·로컬명·약칭은 `OrganizationAlias`(organization.prisma)로 이미 등록 가능. 행정기구 이름이 시대별로 바뀌는 경우 여기서 관리하면 됨.
- **OrganizationHierarchy 기간**: `startDate`/`endDate`가 있어 “1900년에는 A 산하, 1950년부터 독립”처럼 시대별 계통 변경을 저장할 수 있음.
- **역사적 국가 상세 페이지**: 행정기구 섹션을 넣을 때, “역사적 국가” 상세 화면이 있는지·라우트 구조를 먼저 확인하면 진입점 설계에 유리함.

## 5. 중복·일관성 정리 (이렇게 하면 중복 없고 문제없는지)

### 5.1 중복이 생기지 않으려면: “한 가지 기준” 정하기

| 구분 | 내용 |
|------|------|
| **가능한 중복** | 행정기구를 **Organization**과 **AdministrationDepartment** 두 곳에 모두 넣으면, 같은 “외교부”를 두 테이블에 따로 등록할 수 있어 **중복**이 됨. |
| **권장** | **한 가지를 기준**으로 정한다. **(A) 행정기구는 전부 Organization만 사용** (현대·역사 모두). AdministrationDepartment는 “현대 국가 행정 부서 전용”으로 쓰되, **행정기구 계통은 Organization + OrganizationHierarchy로만** 가져가면 AdministrationDepartment는 단순 부서명/계층용으로만 두거나, 아예 쓰지 않고 Organization만 쓴다. **(B)** 또는 “현대 국가 = AdministrationDepartment, 역사적 국가 = Organization”으로 **역할을 나누면** 같은 개념을 두 테이블에 넣지 않으므로 중복 없음. |

→ **정리**: **(A) Organization만 쓰는 쪽**을 추천. 현대/역사 한꺼번에, 계층도 OrganizationHierarchy 하나로, API·UI도 한 흐름으로 관리 가능. AdministrationDepartment는 기존 화면 유지용으로만 쓰거나 점차 Organization으로 통합하는 방향이면 **중복 없고 문제없음**.

### 5.2 직위 정의에서 organizationId + departmentName

- **GovernmentPositionDefinition**에 `organizationId`(FK)를 넣고, 기존 `departmentName`(문자열)은 유지하는 경우: **중복이 아니라 보완**.
  - `organizationId`: “어느 조직 소속인지” 구조적 연결·필터·트리 표시용.
  - `departmentName`: 표시용·과거 명칭·FK 없이 쓰던 기존 데이터 호환용.
- 표시할 때는 “organizationId 있으면 해당 Organization.name(또는 별칭) 쓰고, 없으면 departmentName 사용”처럼 규칙 하나만 정하면 됨. **동시에 두 값 유지해도 일관성 문제 없음**.

### 5.3 인물 경력(GovernmentCareer) + Organization

- **GovernmentCareer**는 이미 `organizationId`(Organization FK)를 갖고 있음. 행정기구를 Organization으로 등록해 두면, 경력의 “소속 기관”은 그 조직을 가리키면 됨. **같은 조직을 여러 경력이 참조하는 구조**이므로 중복 아님.
- 다만 **GovernmentCareer는 countryId만 있고 historicalCountryId는 없음**(체크리스트 13번). 따라서 “조선 이조판서”처럼 역사적 국가 관직은 **이 테이블로는 저장 불가**. 역사적 국가는 Tenure 등 다른 경로만 쓰기로 하거나, 나중에 GovernmentCareer에 historicalCountryId를 넣는 식으로 **정책만 정해 두면** 중복·꼬임 없음.

### 5.4 결론

- **행정기구 = Organization 한 곳에만 등록**, **계통 = OrganizationHierarchy만 사용**하고,  
  현대 국가도 행정기구는 Organization으로 통일하면 **중복 없음**.
- **직위**는 `organizationId` + (선택) `departmentName`으로 **역할 나누기**만 하면 되고,  
  **인물 경력**은 Organization 참조만 쓰면 되며, **역사적 국가 경력**은 13번처럼 정책만 정하면 **문제없음**.

## 6. 역사적 국가 ↔ 현대 국가 연결 (릴레이션)

역사적 국가가 “어느 현대 국가의 과거”인지 연결하려면 **다대다 릴레이션 테이블**을 씁니다.

| 항목 | 내용 |
|------|------|
| **테이블명** | `historical_country_modern_country` |
| **모델명** | `HistoricalCountryModernCountry` (historical.prisma) |
| **컬럼** | `historical_country_id` (과거 국가), `modern_country_id` (현대 국가) |
| **역할** | 조선 → 대한민국, 고려 → 대한민국처럼 “이 역사적 국가가 이 현대 국가의 전신/관련”이라고 등록 |

**확인 방법**

- DB: `SELECT * FROM historical_country_modern_country WHERE historical_country_id = '등록한_역사적_국가_ID';`
- 연결이 없으면 해당 역사적 국가는 “현대 국가 하위”로만 보이는 목록에는 안 나옵니다 (GET /historical-countries에는 나옴).

**연결 방법**

- **API**: 역사적 국가 생성/수정 시 `parentModernCountryIds`에 현대 국가 ID 배열을 넣으면, 백엔드가 위 테이블에 행을 생성/갱신합니다.
- **UI**: 연대표 > 국가에서 역사적 국가 등록/수정 폼에 “연결할 현대 국가”를 선택해 저장하면 됩니다.
